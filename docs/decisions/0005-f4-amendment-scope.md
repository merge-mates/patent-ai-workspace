# 0005. 대비 단위와 보정 범위를 나눈다 (F4가 거절 대상 밖 종속항을 보정에 쓴다)

## 상황
지금은 판단 단위 하나가 두 가지 일을 같이 한다.
- F3 대비 범위: 심사관이 거절한 항을 인용문헌과 대비한다.
- F4 보정 범위: 보정 후보에 쓸 수 있는 항을 정한다.

판단 단위는 거절이유의 대상 항만 독립항별로 묶는다 (`f3_claim_compare/units.py:67-104`). F4는 이 단위의 항만 모델에 보여 주고, 모델 답에 단위 밖 항이 있으면 출력 검사에서 떨어뜨린다 (`f4_response_draft/directions.py:265, 283-287, 365-367`). 그래서 실무에서 흔한 두 보정을 F4가 만들 수 없다.
- 거절 대상이 아닌 종속항의 특징을 독립항에 합치고 그 종속항을 삭제하는 보정
- 그 결과 따라오는 인용 번호 정정

반면 도메인 문서와 요구사항은 이 보정을 처음부터 예상했다.
- 대응 방향 단위 = "거절이유 × 독립항 묶음(독립항 + 그 종속항들)" ([청구항 단위](../product/domain/청구항_단위와_보정방식.md) 50줄)
- 특허 가능한 청구항은 "그 종속항 특징을 독립항에 합치기" 후보의 가장 직접적인 단서 (같은 문서 41줄)
- F4 요구사항 예시 "종속항 3 특징을 독립항에 합치기" ([F4 requirements](../features/F4/requirements.md) 24줄)
- F4 필수 7번 사건 전체 검사 "독립항 보정이 종속항에 번짐, 삭제 뒤 인용 번호". 아직 없다 (`core/cases/case_check.py:26` `NOT_CHECKED`)

구현하면서 대비에 맞춘 좁은 정의가 보정 범위까지 정하게 됐다.

**관찰 (OA 파일럿 네 건, git 밖 실험 기록, 이슈 #345):** 실제 제출 보정서에 적힌 24항 가운데 9항이 F4 범위 밖이었다. 9항은 세 종류다.
- 종속항을 독립항에 합치고 삭제: 2항. 한 건은 심사관의 특허 가능 힌트가 있었고, 한 건은 힌트 없이 출원인이 골랐다.
- 삭제에 따라오는 인용 정정: 4항
- 이유를 자료로 확정할 수 없음: 3항

힌트가 있던 건에서 F4 요청 프롬프트에는 그 종속항 글자가 없었다. 반면 단위 밖 항까지 보여 준 별도 분류 실험에서는 모델이 이유 칸에 "그 종속항을 독립항에 합치는 보정"을 썼다. 다만 "불확실하면 유지" 지시 때문에 결정은 유지로 냈다 (1회 관찰).

되돌리기 어렵고(F4 입력·출력 검사·채점 분모가 바뀜), 이유를 모르면 "거절되지 않은 항을 왜 고치나"가 이상해 보이고, 진짜 선택지가 넷 있다.

## 결정
제안: ③. 판단 단위(`JudgmentUnit`)는 F3 대비 단위로 그대로 둔다. F4는 묶음마다 **보정 범위**를 따로 계산해 모델 입력과 출력 검사에 쓴다. 따라오는 정정은 사건 전체 검사(코드)가 계산한다.

1. **인용 관계표 (코드 도구, 모델 호출 없음):** OA 당시 청구항 전체에서 항마다 인용하는 앞 청구항 번호를 뽑는다.
   - 인용 표시("제N항에 있어서", "제N항 또는 제M항", "제N항 내지 제M항")를 읽는다.
   - 못 읽은 항은 `depends_on = null` + 확인되지 않음 + 경고로 둔다 (못 찾음 ≠ 없음).
   - 지금 F3 청구항 나누기(`SplitClaim.depends_on`)는 거절 대상 항과 그 항이 거슬러 인용하는 앞 항만 모델로 나누고(`f3_claim_compare/run.py:64-110`), `F3Result`에도 실리지 않는다(`f3_claim_compare/result.py:76-89`). 거절 대상을 인용하는 뒤 종속항은 표에 없다. 그래서 F4가 쓸 표를 따로 만든다.
   - 질문: 이 표를 F3 청구항 나누기와 한 곳에서 만들지 (같은 규칙을 두 곳에 두지 않으려면).
2. **보정 범위 (코드 도구):** 묶음의 보정 범위 = **같은 거절이유의 진보성·신규성 묶음 전부**의 독립항(대상 항이 종속항뿐이면 거슬러 올라간 독립항) + 그 독립항을 거슬러 인용하는 모든 종속항.
   - (Claude 고침, 2026-11-24) 처음 초안은 "그 묶음의 독립항 + 종속항"이었다. tune 8건 점검에서는 병렬 독립항(장치·방법·매체)에 청구항 1의 종속항 특징을 같이 넣은 보정이 많았다. 처음 정의는 출처 23쌍 중 13쌍만 덮었고, 고친 정의는 23쌍을 다 덮는다 (4건 10쌍 차이, [실험 카드](../../experiments/m3-i2-f4-amendment-scope/card.md) "0번 사전 점검 결과").
   - 여러 항을 인용하는 종속항("제1항 또는 제2항", "제1항 내지 제12항")은 인용 가지가 닿는 독립항마다 그 범위에 들어간다. 그래서 한 항이 두 묶음의 범위에 함께 들 수 있고, 둘 다 고치려 하면 아래 6번 겹침 규칙을 따른다.
   - 명확성 묶음은 지금처럼 그 항 + `read_with`만 둔다 (명확성 보정은 그 항 안에서 끝나는 경우가 대부분이라 판단. 다시 볼 조건 아래).
   - 범위가 대상 항보다 넓으면 넓어진 항 번호를 묶음 결과에 남긴다 (화면·채점이 "AI가 거절 대상 밖 항을 제안했다"를 구분하게).
3. **F4 입력:** 보정 범위 전체의 청구항 글자와 인용 관계표를 프롬프트에 넣는다. 특허 가능 항 힌트는 지금처럼 넣는다.
   - 거절 대상 항과 범위만 넓힌 항은 프롬프트에서 따로 표시한다. 범위만 넓힌 항에는 F3 대비가 없다는 것도 적는다.
4. **F4 출력 검사:** `amendment_core`에 쓸 수 있는 항 = 보정 범위 (`f4_response_draft/directions.py:265`의 `allowed_claims`).
   - 보정 초안 단계도 같이 바꾼다. 지금 보정 프롬프트는 "이 판단 단위 밖의 청구항은 고치지 않습니다"라고 하고(`prompts/f4/amendment.md:9`) 단위 안 청구항 글자만 받는다. 이것도 보정 범위 기준으로 바꾼다.
   - 종속항 특징을 합칠 때 출처 항 번호는 이슈 #238 `AmendmentCore.source_ref`로 남긴다. 이것이 없으면 "어느 종속항을 합쳤나"를 채점할 수 없다.
5. **따라오는 정정 (사건 전체 검사, 요구사항 7번):** 묶음별로 고른 방향의 `amendment_core`를 모아 계산한다.
   - 삭제된 항을 인용하던 항 → "인용 번호 정정 필요" 표시
   - 보정된 독립항을 인용하는 종속항 → "번짐 확인 필요" 표시
   - 표시만 하고 글자는 고치지 않는다. 사람이 정한다 (보정 적법성 판정 아님).
   - 질문: 인용 번호만 바꾼 보정 초안 글자까지 코드가 만들지.
6. **겹침:** 범위가 넓어지면 두 묶음이 같은 종속항을 고치려는 경우가 늘 수 있다. 지금 `amendment_overlaps`(`f4_response_draft/amendment.py:255-282`)가 `needs_human_review`로 드러내는 규칙을 그대로 쓴다.

정하지 않는 것:
- 특허 가능 힌트를 코드가 "합치기" 후보로 자동으로 만들지. 지금은 요구사항 점수 기준의 단순 규칙 비교 대상으로만 둔다 ([F4 requirements](../features/F4/requirements.md) 점수 1 질문).
- 범위만 넓힌 종속항을 F3가 대비할지. 아래 다시 볼 조건.

## 결과
- 쉬워지는 것: 종속항 병합·삭제 후보가 구조상 가능해진다. 따라오는 정정이 모델 판단이 아니라 코드 검사로 빠짐없이 드러난다. F3와 F3 채점은 그대로다.
- 어려워지는 것:
  - 프롬프트가 길어지고 모델이 볼 항이 는다.
  - F4 방향 채점에서 "거절 대상 밖 항을 제안함"을 맞음·틀림 어느 쪽으로 셀지 정해야 한다. 실제 보정서 정답이 범위만 넓힌 항을 포함하는지가 사건마다 다르다.
  - 범위만 넓힌 항에는 대비 근거가 없어, 그 항의 특징이 인용문헌에 있는지는 사람이 본다 (후보 `checks`에 적는다).
- 다시 볼 조건:
  - 힌트 없는 사건에서 범위를 넓혀도 실제로 합친 종속항이 후보에 거의 안 나오면, 범위만 넓힌 종속항의 F3 대비(②의 일부)를 다시 본다.
  - 명확성 보정이 다른 항으로 번지는 사례가 tune에서 나오면 명확성 묶음 범위를 다시 본다.
  - 실제 유지한 항을 바꾸자는 제안이 늘어 사람 검토 부담이 커지면, 범위 안 항에 우선순위를 주는 방식을 다시 본다.
- 확정 절차:
  - 같은 입력·같은 모델(Sonnet)에서 ①과 ③의 F4 방향 후보를 tune OA로 비교한다 (판정용 2회). 계획·문턱: [실험 카드](../../experiments/m3-i2-f4-amendment-scope/card.md)
  - 볼 숫자:
    - 실제 보정서의 정정·삭제 항 중 후보에 나온 비율 (범위 안 / 전체를 따로)
    - 실제로 합친 종속항이 출처로 나온 비율
    - 실제 유지 항을 바꾸자고 한 비율
    - 따라오는 정정 표시가 실제 인용 정정 항을 덮는 비율
  - 숫자와 은진 님 동의가 있으면 상태를 "확정"으로 바꾸고 F4 design 3-1·3-2·8절, 요구사항 7번 줄을 고친다.
- 1차 비교 결과 (2026-11-24, tune 8건, Sonnet 각 2회, [실험 카드](../../experiments/m3-i2-f4-amendment-scope/card.md)):
  - 거절 대상 밖 출처 결정: ① 0/4, ③ 3/4·3/4, 단순 규칙 R 3/4.
  - 문턱 6개 중 5개 통과. "보정 없음 항 변경"은 ③이 2칸 많아 미통과다 (한 묶음에서 합친 종속항을 모델이 같이 정리).
  - 힌트 있는 건은 모델과 R이 같고, 힌트 없는 1건은 방향은 맞았지만 출처가 달랐다.
  - 사후 분석 (모델 호출 0):
    - 규칙 R을 후보에 넣으면 맞힌 결정 수는 같고 정밀도만 떨어진다. 그래서 "힌트를 코드 후보로" 안은 이 세트에서 근거가 없다.
    - 대신 병렬 독립항(장치·방법·매체)에 같은 출처를 넣지 못한 것이 가장 큰 남은 누락이다 (병렬 쌍 1~2/11).
    - 같은 거절이유의 독립항끼리 출처를 맞추는 코드 규칙(K3)을 얹으면 출처 쌍이 9 → 11·13/23으로 오른다. 5번 "사건 전체 검사"의 규칙 후보로 둔다 (결과를 본 뒤 만든 규칙이라 다른 세트에서 따로 잰다).
  - 상태는 제안(비교 중) 그대로 둔다. 카드 "다음" 0번(병렬 독립항 맞추기)과 1번(따라오는 정정을 프롬프트에서 빼기)을 잰 뒤 다시 본다.
