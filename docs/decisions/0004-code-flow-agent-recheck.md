# 0004. 진행은 코드, 근거 다시 찾기만 에이전트 (사건 지휘 에이전트 대신)

## 상황
[ADR 0003](0003-tech-stack.md) "에이전트가 정하는 것과 코드로 고정하는 것"은 지휘 에이전트가 사건 진행(무엇을 어떤 순서로, 더 찾을지 멈출지)을 정한다고 했다. 구현해 보니 지금 `plan: agent`는 도구 4개(F1·F3·F2·F4)의 순서만 고르고 결과를 보지 않는다. tune 10통 fixed_order 실행(11/23, git 밖 일회용 실행, 저장소 실험 카드 없음)에서 끝까지 돈 9통이 모두 같은 순서였고, 어느 기능을 부를지는 거절이유 종류와 자료 유무로 코드가 이미 안다. 반대로 "앞 결과를 보고 다음 행동을 정해야" 하는 곳은 근거를 못 찾은 곳 다시 찾기다 (F3 1차에서 근거 0개인 구성요소, F4 앞 최초 명세서 보정 근거). 에이전트를 어디에 둘지 다시 정해야 한다. 되돌리기 어렵고(그래프·단계 기록·평가 모양이 바뀜), 이유를 모르면 "지휘 에이전트가 없다"가 이상해 보이고, 진짜 선택지가 셋 있다.

## 비교한 선택지 (제안 상태에서도 공유한다)
| 안 | 좋은 점 | 나쁜 점 | 출처 |
|---|---|---|---|
| ① 지금 그대로: 지휘 에이전트가 사건 진행을 정함 (`plan: agent`) | ADR 0003 그대로. 사건마다 다른 진행을 표현할 자리 | 고를 것이 없다 (끝까지 돈 tune 9통이 한 길). 모델 호출이 늘고 테스트·평가가 어렵다 | 11/23 tune 10통 fixed_order 실행 기록 (판단) |
| ② 묶음마다 LLM 지휘가 대비 / 근거 찾기 / 보류 중 고름 | 묶음 단위로 진행이 달라질 수 있음 | 대비는 늘 해야 하고 보류는 규칙으로 정해지고 방향은 F4가 만든다 → 고르는 것이 결과에 거의 안 닿음 | tune 35묶음 중 대비를 건너뛸 묶음은 명확성 19(규칙으로 앎) (판단) |
| **③ 진행은 코드(고정 순서), 근거 다시 찾기 두 자리에만 검색 에이전트** | 에이전트가 필요한 곳(결과를 보고 다음 질의를 정함)에만. 고정 단계·상한·기록을 코드가 지킨다. 같은 자리에 고정 루프를 두고 숫자로 비교할 수 있다 | 고정 루프(질의 다시 쓰기)가 이미 많이 올려 에이전트의 몫이 작을 수 있다. 사건 진행이 달라지는 경우(다른 자료 더 받기 등)는 코드 분기로 더해야 한다 | Anthropic "Building effective agents"(2024-12, 회사 테크 블로그): 정해진 흐름은 workflow, 열린 탐색만 agent. 인용문헌 LLM 질의 다시 쓰기 Hit@10 0.706 → 0.79 수준 (이슈 #225 안건 9 본문, 저장소 실험 카드 없음) |

## 결정
제안: ③. 진행(어느 기능을 어떤 순서로)은 코드가 고정 순서로 정하고, 에이전트(tool use 검색 루프)는 "근거를 못 찾은 곳 다시 찾기" 두 자리에만 둔다. 그 두 자리에서도 지금 방식(A) / 고정 루프(B) / 에이전트 루프(C)를 같은 인터페이스 뒤에 두고, 같은 세트로 잰 숫자로 C를 쓸지 정한다 ([근거 다시 찾기 design](../features/recheck/design.md) 7-3). 사람 승인 전 멈춤·초안 검사·출처 확인·자르기·상한은 0003 그대로 무조건 도는 코드 단계다.
- 판단 단위 나누기(`prepare_units`)는 F3 안에서 꺼내 고정 단계로 둔다 (F2가 F3를 기다리지 않게).
- 0003은 이 제안이 확정될 때까지 고치지 않는다. 지금 `plan: agent` 코드도 그대로 두고 기본은 지금처럼 `fixed_order`다.

## 결과
- 쉬워지는 것: 그래프 테스트(순서가 고정), 비용 예측(에이전트 호출이 근거 0개 구성요소 수에 비례), "에이전트가 필요한 곳인가"를 숫자로 보이기.
- 어려워지는 것: 사건마다 진행을 바꾸는 일(예: 자료가 모자라면 더 받으러 감)은 코드 분기로 더해야 한다.
- 다시 볼 조건: C가 B보다 낫지 않으면(7-3 판정) 에이전트 루프는 쓰지 않고 B 또는 A를 기본으로 둔다. 사건 진행이 tune·report에서 실제로 갈리는 경우가 나오면 지휘 에이전트(①)를 다시 본다.
- 확정 절차: 비교 숫자(판정용 2회) + 은진 님 동의 → 상태를 "확정"으로 바꾸고 0003의 "에이전트가 정한다" 줄을 "대체됨(→ 0004)"로 표시한다.
