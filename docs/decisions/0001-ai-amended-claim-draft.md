# 0001. AI 대응 방향 제안과 검토용 보정 청구항 초안

## 상황
이전 기획서(v3.0)는 "AI는 의견서 초안만 쓰고, 보정 청구항은 변리사가 직접 작성하며, AI는 대응 전략의 우열을 추천하지 않는다"로 합의했다. 이후 OA 대응 흐름을 구체화하면서 "AI가 대응 방향을 제안하고 검토용 보정 청구항 초안과 최초 명세서 근거 후보까지 보여 주자"는 제안이 나왔다. 받아들이면 AI가 하지 않는 일 목록이 바뀐다.

## 비교한 선택지
| 안 | 좋은 점 | 나쁜 점 |
|---|---|---|
| A. 이전 합의 유지: 변리사가 보정안 입력, AI는 검증·의견서 초안 | 책임 경계가 분명. 평가가 쉬움 (입력된 보정안 대조) | 사용자가 빈 화면에서 시작 |
| B. AI가 대응 방향 후보 + 검토용 보정 청구항 초안, 사용자가 확인·수정 | AI가 먼저 초안을 준비하는 경험. 유사 서비스도 초안을 준다 | 법적 적절성은 변리사 평가 없이 검증 한계. 신규사항 등은 자동 판정 불가. 범위가 커짐 |
| C. 사용자가 요청할 때만 B를 켬 (선택 기능) | A를 기본으로 두고 B를 실험 가능 | 흐름이 두 갈래 |

## 결정
B안 (2026-11-13 확정). AI가 사건 전체의 대응 방향 후보(11/16 보완으로 바뀜: 거절이유 × 독립항 묶음, 아래 보완 문단)와 검토용 보정 청구항 초안·최초 명세서 근거 후보를 먼저 보여 주고, 사용자가 확인·수정하거나 직접 쓴다. 최종 채택·승인은 사람이 한다.

흐름: AI가 대응 방향 후보 2~3개 제시(11/16 보완으로 바뀜: 순위·이유·확신도, 아래 보완 문단) → 사용자가 선택 → 고른 방향으로만 의견서·보정 초안 작성. 방향을 고르기 전에 후보마다 초안을 미리 쓰는 방식은 확장 후보로 둔다 (기획서 14절).

3주 구현에 넣을지는 [ADR 0002](0002-first-build-scope.md)에서 넣기로 정했다.

2026-11-16 보완 (팀 확정): 대응 방향 후보에 순위·이유·확신도를 붙인다. 단위는 거절이유 × 독립항 묶음이고, 마지막에 사건 전체를 검사한다. 확신이 낮으면 순위 없이 "직접 판단 필요"로 둔다. 후보 수 상한과 확신도 기준선은 설정 파일 값으로, 돌려 본 뒤 정한다. 최종 선택·채택·제출은 사람이 한다.

2026-11-17 보완 (팀 확정, PR #5 리뷰 반영):
- 단위는 거절이유마다 다르다. 진보성은 독립항 묶음이다: 독립항을 먼저 보고, 독립항이 서면 그 종속항도 서며, 무너진 묶음만 종속항을 따로 본다 (심사기준 3330쪽). 신규성도 같은 순서로 보되 결과는 청구항마다 남긴다 (심사기준 3214·5204·5339·2419쪽으로 받친 추론). 명확성은 청구항마다 다 보고, 종속항은 인용하는 앞 청구항 문구까지 함께 읽는다 (심사기준 2407~2411쪽). 명확성에서 묶음은 보여 주기만 하고, 앞 청구항의 불명확을 물려받는다는 표시는 추론이다 ([청구항 단위](../product/domain/청구항_단위와_보정방식.md)).
- 여러 항을 "또는"으로 인용하는 종속항은 인용하는 독립항마다 가지를 나눠 각 묶음을 따른다 (심사기준 3226쪽). 두 독립항을 모두 포함하는 청구항은 두 묶음에 걸치고, 하나라도 서면 선다 (추론). 가지끼리 결과가 엇갈리면 사건 전체 검사에서 표시하고 사람이 정한다.
- 묶음마다 1등 후보가 "AI 기본값"으로 미리 선택된 상태가 기본이고 사람이 바꿀 수 있다. 화면과 데이터에서 AI 기본값과 사람이 고른 것을 구분한다. 확신도가 "낮음"인 묶음은 미리 고르지 않고, 사람이 고를 때까지 그 묶음의 초안만 보류한다. 나머지 묶음은 진행한다.
- 확신도는 높음 / 중간 / 낮음 3단계다 (% 숫자로 내지 않는다). 낮음이면 순위 없이 "직접 판단 필요". 단계 기준은 설계에서 정하고, 기준값은 설정 파일에 둔다.

## 결과
- AI가 하지 않는 일은 방향 확정, 적법성 판정, 등록 가능성 보증, 자동 제출로 좁혀진다. 방향 순위는 "검토 순서 제안"이며 성공 보증이 아니다 (기획서 13절).
- 평가: 실제 변리사가 택한 방향과의 일치율(1등, 실제 방향의 순위, 확신도 단계별)을 잰다. 실제 방향은 보정서·의견서 기록(청구항별 한정·부가·삭제·그대로)에서 뽑는다. 의견서는 있고 보정서가 없으면(출원번호 + 발송번호로 확인) 보정 없이 반박으로 보고, 출원 이력을 다 확인하지 못한 사건은 평가·개발 세트에서 뺀다. 초안은 실제 방향을 넣고(oracle) 따로 잰다. 자세한 틀은 [product.md](../product.md) 6절.
- 보정안의 법적 적절성은 변리사 평가 없이 검증 한계가 있다. 평가는 근거 위치·변경 내용·의견서 일치처럼 확인할 수 있는 항목부터 잰다.
