## 무엇
변리사가 OA 대응 중이거나 사건 없이 법률 질문을 하면, AI가 법령(특허법·시행령)·특허·실용신안 심사기준·판례에서 근거를 찾아, 답변의 주장마다 출처(자료 종류·식별자·판본)와 원문 위치를 붙여 돌려준다.
근거를 찾지 못했거나 판본을 모르면 지어내지 않고 이유와 함께 "확인되지 않음"·"조회 범위 내 없음"으로 남긴다. 근거가 그 사건에 적용된다고 판단하지는 않는다.

- 핵심은 **무엇을 찾을지(검색 대상과 질의)와 찾은 것을 어떻게 재는지(검색 평가)**다. 답변 글은 그 근거를 묶는 겉이다.
- 같은 기능을 두 길에서 쓴다: OA 흐름(지휘 에이전트가 지적마다 자동으로 부름, 먼저 만듦)과 사건 없는 법률 질문(여러 번 묻고 답함, 나중에 만듦) ([product.md](../../product.md) 10절 만드는 순서).

## 사용 장면 (1~3개)
1. 변리사가 진보성 지적을 보면서, 그 OA 발송일에 시행 중이던 특허법 29조 2항과 심사기준의 진보성 판단 부분, 반박에 쓸 만한 대법원 판결을 원문 위치와 함께 한곳에서 보려 한다.
2. 변리사가 명확성 지적("상기 ○○"에 앞의 근거가 없음)을 받고, 42조 4항 2호와 심사기준의 명확성 사례가 OA 당시 판에서 어떻게 적혀 있었는지 확인하려 한다.
3. 변리사가 사건 없이 "신규성 판단에서 공지예외 주장은 언제까지 해야 하나"를 묻고, 답을 본 뒤 "2020년 기준으로는?"이라고 범위를 좁혀 다시 묻는다.

## 입력과 출력
- **입력 자료:**
  - 검색할 자료 (데이터 카드 [`docs/data/law-go-kr.md`](../../data/law-go-kr.md)):
    - 특허법 14판·시행령 3판 조문: 색인 `law-idx-v2`에 있음 (조각 10,649개, BM25·벡터).
    - 특허·실용신안 심사기준 8판 (2018.1.1 ~ 2026.3.13, PDF): 아직 색인 없음 → `law-idx-v3`에서 넣는다 (#24).
    - 판례 74건 (진보성 30, 명확성 29, 신규성 15. JSON, 판시사항·판결요지·판례내용): 아직 색인 없음 → `law-idx-v3`에서 넣는다 (#24).
    - 심결례 12건: 11/17에 kipris.or.kr 심판 검색에서 받은 컴퓨터 비전(IPC G06T·G06V) 거절결정불복 심결문 PDF (진보성만 5, 명확성만 1, 신규성+진보성 3, 진보성+명확성 1, 명확성+다른 이유 2). 새 저장소 `data/raw/trials_cv_1117/`에 있고 카드는 [trials-kipris.md](../../data/trials-kipris.md) (#24). 색인은 `law-idx-v3`. 그 밖 심결은 열린 질문 3.
  - OA 흐름에서 받는 것: F1 ① `OAResult`의 거절이유(조문·심사관 논리 글·대상 청구항)와 OA 발송일·출원일. 청구항 글은 OA 당시 청구항 판만 쓴다. **등록공보는 AI 입력에 넣지 않는다** ([product.md](../../product.md) 8절).
  - 법률 질문에서 받는 것: 자유 입력 하나(질문·쟁점·키워드·사건번호) + 선택 조건(시점, 자료 유형).
- **필요한 판:**
  - 법령: 시점이 있으면 그날 시행 중인 판. 시점이 없으면 현행 판 + 확인 기준일.
  - 심사기준: 같은 규칙 (예규 번호·시행일로 판을 가름).
  - 판례: 판본이 없다. 사건번호·선고일이 식별자다.
  - OA 흐름의 시점은 OA 발송일을 **검색 기준일**로 쓴다. 이것을 그 사건의 적용 기준일로 확정하지 않는다 (출원일 기준 판과 다르면 둘 다 보인다, 합격 기준 3).
- **출력:** [`docs/data-model.md`](../../data-model.md) 4절 ④ `LegalEvidenceBundle`. 법률 질문은 그 겉에 대화 `LegalChat` (칸은 design.md 3-2절에서 새로 정함).
- **예시:** 지어낸 조문·심사기준 문단·판례 조각과 지어낸 질문 `tests/fixtures/f2/` (실제 원문은 넣지 않음). 목록은 design.md 9절.

## 합격 기준 (테스트로 바꿀 수 있게)
1~8은 [product.md](../../product.md) 5절 F2와 같다. 아래 줄은 그 기준을 테스트로 바꾼 것이다. 9·10은 6절 평가에서 왔다.

1. 질문·쟁점·키워드·사건번호를 자유 입력 하나로 받고, 시점·자료 유형은 선택 조건으로 받는다. 자연어와 선택 조건이 부딪히면 사용자에게 확인한다. (필수)
   ← 질문 "2020년 기준 진보성 판단" + 선택 시점 2023-01-01 → 조사는 시작하되(2번) 시점 확인 요청 1건이 나온다
   ← 사건번호만 넣은 입력 "2007후3660" → 판례 식별자로 읽는다
2. 확인을 기다리지 않고 할 수 있는 조사부터 시작한다. 실제로 한 주요 작업 상태만 보이고(세부 과정 중계 없음), 사용자가 범위를 바꾸면 알리고 이전에 확인한 자료는 보존한다. (필수)
   ← 1번의 부딪힘 입력: 판례·심결 검색은 두 날짜 중 이른 날까지로 끝나 있고(어느 쪽으로 확인돼도 쓸 수 있는 범위), 판본이 갈리는 조문·심사기준 조회만 확인을 기다린다 (design.md 4절)
   ← 대화에서 두 번째 질문이 시점을 바꾸면 "범위가 바뀌었음" 알림 1건, 첫 답의 확인된 근거가 두 번째 답의 "이전에 확인한 자료"에 그대로 남는다
3. 시점이 없으면 현행 자료로 답하며 확인 기준일을 표시한다. 시점이 있으면 그 시점 판본 후보를 찾고, 판본을 모르면 "확인되지 않음"(`edition_unknown`)을 돌려준다. 사용자가 준 날짜를 그 사건의 적용 기준일로 자동 확정하지 않는다. (필수)
   ← 시점 없음 → 오늘을 기준일로 검색해 현행판 조각만 + `checked_on` (같은 조문의 옛 판이 섞이지 않음)
   ← 시점 2020-05-04 → 그날 시행판 조각만 (검색 계약 `as_of`)
   ← 판본 모름 조각만 있는 조문 → `unverified(edition_unknown)` ("조회 범위 내 없음"이 아님)
   ← OA 흐름: 발송일판과 출원일판의 그 조문 글이 다르면 근거는 발송일판, 출원일판은 "추가 검토할 자료"로 같이 보이고 "확인 필요" (`conflict`가 아니라 사람이 정할 일, 열린 질문 4)
   ← 결과 어디에도 "적용 기준일" 칸이 없다 (스키마 검사)
4. 답변의 주장마다 출처(자료 종류·식별자·판본)와 원문 위치를 붙인다. 확인하지 않은 위치는 붙이지 않는다. (필수)
   ← 주장마다 `evidence` ≥ 1, 위치는 조문 `제29조제2항`(조각 `loc_label` 그대로) / 심사기준 쪽(+절) / 판례 "이유 1" 같은 원문 표기
   ← 위치의 원문 글이 저장된 조각에 없으면 그 근거는 빠지고 주장은 "확인되지 않음" (출처 확인 단계, design.md 2절)
5. 판례·심결례는 전문/요지, 판단/당사자 주장을 구분해 표시한다. (필수)
   ← 판결요지 조각에서 온 근거 = `요지`, 판례내용 조각 = `전문`
   ← 전문 근거는 법원 판단 / 당사자 주장 / 모름 중 하나. 모름이면 "확인 필요"로 보이고 판단처럼 쓰지 않는다
6. 근거 검토: 출처가 실제로 있는지, 위치·판본이 맞는지, 원문이 주장을 뒷받침하는지 확인하고, 안 맞으면 고치거나 "확인 필요"로 표시한다. (필수)
   ← 오류 주입 사례 5종(없는 출처, 주장–원문 불일치, 다른 시점 판본을 적용으로 단정, 요지만 보고 전문이라 쓰기, 개정 전 기한을 현행처럼 씀)이 각각 잡힌다 (#35 사례)
7. 근거를 확인하지 못하면 F5 상태에 이유를 붙여 구분한다. "조회 범위 내 없음"은 찾아봤지만 없음(미발견), "확인되지 않음"은 조회 실패 / 본문 미확보 / 판본·적용 미확인 중 하나다. 중요한 반대 자료와 미확인 후보는 "추가 검토할 자료"로 따로 둔다. (필수)
   ← 검색 결과 0개 → `not_found_in_scope` + 찾아본 범위(말뭉치·색인 판·자료 유형·기준일)
   ← 받은 12건 밖의 심결을 물으면 → `not_found_in_scope` + 찾아본 범위(받은 심결 12건). 색인 전이면 `unverified(body_missing)`
   ← 주장과 반대로 판단한 판례 조각이 검색에 나오면 버리지 않고 "추가 검토할 자료"에 남는다
8. OA 흐름에서는 지휘 에이전트가 지적 정보로 질문을 만들어 부른다. 찾은 근거는 출처·판본·미확인 상태와 함께 AI 생성으로 사건에 들어간다. 근거가 그 사건에 적용된다고 판단하지 않는다. (필수)
   ← 거절이유 3개(진보성·명확성·신규성)인 가짜 `OAResult` → 거절이유마다 ④ 하나, `origin = ai_generated`, 사건에 저장
   ← 질의에 등록공보 글이 0자 (입력 자료 검사)
   ← 사건 적용 표현 검사: 답변 글(따옴표 안 원문 인용은 뺌)에 "이 사건에 적용"·"등록 가능" 같은 표현이 있으면 그 주장에 "확인 필요" (판례 원문의 "적용된다"·"부적법"은 걸리지 않음)
9. (AI, 검색) tune 세트에서 법령 조문 검색 Hit@1 ≥ [확인 필요: 기준선 뒤] (같이 Recall@5), 심사기준·판례 검색 Hit@k·Recall@k 한 줄씩. 못 찾은 질문은 채점 실행에서 CQ 후보로 쌓이고 0건이면 경고한다. 심사기준·판례 정답 줄이 생기기 전(열린 질문 5)에는 그 유형 CQ가 0건 + 경고인 것이 정상이다. (필수)
   - 지금 기준선: 조문 BM25 Hit@5 1.000·Recall@5 0.974 / 벡터 Hit@5 0.316·Recall@5 0.289 (tune v2, 19줄, [experiments/index.md](../../../experiments/index.md)). Hit@5·Recall@5가 이미 1.000·0.974라 주 지표를 Hit@1로 둔다 (design.md 7-1).
   - 줄은 검색 계약대로 거절이유 하나다. 보고는 줄 평균 + **OA 한 통 단위**(그 OA의 모든 거절이유 줄이 Hit인 비율)를 같이 낸다. **정함 (재아 님 11/20 동의).**
10. (AI, 근거 검토) 근거 검토 세트(실제 질문 + 오류 주입, 20개 이상)에서 출처 존재·위치·판본 일치율, 주장 뒷받침 판정 정확도, 주입 오류 탐지율·고친 비율 ≥ [확인 필요: 기준선 뒤]. 없는 출처를 근거로 낸 답 0건, 확인하지 않은 원문 위치 0건은 문턱과 상관없이 지킨다. (필수)

- 낱말 뜻: **주장** = 답변에서 근거 하나 이상이 붙는 한 문장. **근거** = 저장된 조각 하나의 위치(검색 계약 `SearchHit`)와 그 원문 글. **추가 검토할 자료** = 주장에 쓰지 않았지만 사람이 봐야 할 조각(반대 판단, 판본 모름 후보).

## 근거
- 이 기능 결과의 근거: 저장된 조각(법령 조문·심사기준 문단·판례 문단)의 `doc_id` + 원문 위치 + 판본 + 색인 판 (검색 계약 design 3-2절). 조각 밖의 글(모델이 기억으로 쓴 조문·판례)은 근거가 아니다.
- 앞 기능 결과가 "확인되지 않음"이면:
  - F1 거절이유의 조문이 `unverified`이면 조문 조회를 하지 않고, 심사관 논리 글로만 심사기준·판례를 찾는다. 결과는 `input_unverified`.
  - OA 발송일이 `unverified`이면 시점 없이 현행으로 찾지 않는다. 조문·심사기준 조회와 판례·심결 검색을 보류하고(판례도 선고일로 거를 날짜가 없음) 사람에게 날짜를 확인받는다.
  - 거절이유가 지원 안 하는 종류(`other`)면 F2를 부르지 않는다 (F1이 "직접 검토 필요"로 둠).

## 사람이 고르거나 고치는 곳
- F2 결과(④)는 중간 결과라 사람이 고치지 않는다 ([product.md](../../product.md) 3.3절).
- 사람이 하는 것: 자연어와 선택 조건이 부딪힐 때 확인, 시점(판본)을 모를 때 날짜 정하기, 발송일판·출원일판이 다를 때 어느 판을 볼지 판단, 근거가 그 사건에 적용되는지 판단.
- 법률 질문에서 질문을 고쳐 다시 묻는 것은 새 질문이다 (앞 답은 남음).

## 실패할 때
- **색인에 그 자료 유형이 없을 때** (예: `law-idx-v3` 전이라 심사기준·판례 없음): 그 유형은 `unverified(body_missing)` + "색인에 없음"으로 두고 조문 조사는 끝까지 한다.
- **그날 판이 색인에 없을 때** (기준일이 색인의 가장 이른 판보다 앞섬): 결과 0개를 "조회 범위 내 없음"으로 내지 않는다. 조문은 법령 API로 조회하고 실패하면 `lookup_failed`, 심사기준은 `edition_unknown`.
- **검색 결과 0개:** `not_found_in_scope` + 찾아본 범위. 질의를 바꿔 한 번 더 찾고(최대 횟수는 설정), 그래도 없으면 끝낸다. 없다고 단정하지 않는다.
- **법령 API 조회 실패 (색인에 없는 판을 찾을 때):** `unverified(lookup_failed)`, 다시 조회할 수 있게 남긴다.
- **모델 호출 실패:** 다시 부르기(설정 `max_retries`) 뒤에도 실패하면 그 질문의 실행을 `failed`로 끝내고, 이미 확인된 근거 조각 목록은 버리지 않는다. 빈 답을 성공으로 내지 않는다.
- **근거 검토가 주장을 뒷받침하지 않는다고 볼 때:** 근거를 바꿔 한 번 고치고, 그래도 안 맞으면 주장을 "확인 필요"로 둔다 (지우지 않음).
- **상한(호출 수·시간·비용)에 닿을 때:** 거기서 멈추고 확인된 것까지만 낸다. 남은 거절이유에도 ④를 하나씩 저장하고 "확인되지 않음(조사 상한)"으로 둔다. ④가 없는 거절이유를 뒤 기능이 "근거 없음"으로 읽지 않게 하려는 것이다. 이유 코드는 공통 칸 PR(#29)에서 더한다 (design.md 2절).

## 비교 실험
예 ([product.md](../../product.md) 3.1절).
- 축 1 (PRD): 근거 검토 역할 분리 있음 / 없음. 있음 = 답을 쓰는 서브에이전트와 근거 검토 에이전트가 따로, 없음 = 한 에이전트가 쓰고 스스로 검토. 같은 근거 검토 세트(10번)로 품질 + 시간·비용·호출 수를 잰다.
- 축 2 (검색, 검색 계약 위): 무엇을 찾을지와 어떻게 찾을지. 질의 모양(거절이유 본문 전체 / 결론 문장만 / 모델이 다시 쓴 질의), BM25 / 벡터 / hybrid, 임베딩 모델. 한 말뭉치 안에서만 비교한다 (검색 계약 requirements "무엇").
- 축 1 정함 (은진·재아 11/20): 근거 검토 분리(`split`)를 기본으로 구현한다. 쓴 쪽이 스스로 검토하면 같은 착각을 같이 놓치기 쉽고, 근거 검토 에이전트를 F2·F3·F4 공통으로 따로 두는 것은 11/16에 정했다. `single`/`split` 비교는 M2 일정에서 빼고 M3에 시간이 나면 한 번 돌린다 (같은 코드에서 검토를 끄는 설정 하나). product.md 3.1 F2 "비교 실험 예"·주인 "둘"은 이 결정에 맞춰 따로 PR로 고친다.
- 구현 방식: 한 사람(은진)이 구현하고 같은 인터페이스 뒤에서 설정(`impl`, 질의 모양, 모델)만 바꿔 비교한다. 둘이 각자 구현하지 않는다. 이유: F3도 비교 실험이라 둘 다 F2를 따로 만들 시간이 없고, 검색 기준선(#66)이 이미 `impl` 설정으로 비교하고 있다.

## 화면 흐름과 API
- 화면 (OA 흐름): 거절이유 하나 열기 → 법률 근거(조문·심사기준·판례) 목록, 주장마다 출처·위치·판본·상태 → 원문 위치 누르기 → "추가 검토할 자료" 펼치기. 화면은 #34.
- 화면 (법률 질문): 질문 쓰기(+ 시점·자료 유형 고르기) → 주요 작업 상태 → 답과 근거 → 이어 묻기.
- API (명세 [api/README.md](../../api/README.md)): `GET /oas/{oa_id}/legal-evidence` (④, 있음), `POST /legal-chats`, `POST /legal-chats/{id}/messages`, `GET /legal-chats/{id}` (자리만 있음, 칸은 design.md 3-2절).

## 안 할 것
- 근거가 그 사건에 적용되는지, 등록 가능한지 판단 (CLAUDE.md 특허 도메인 규칙).
- 법률 조사 보고서 작성·내보내기, 조사 기록 이어 하기 (L7~L9, [product.md](../../product.md) 3.3절). 대화는 저장하지만 "이어 하기" 기능은 없다.
- 사람이 F2 결과를 고치기.
- 지식 그래프 검색: M2에는 넣지 않는다. M3 조건부 여부는 [ADR 0002](../../decisions/0002-first-build-scope.md) 11/18 보완대로 11/24에 정한다 (강사님 조언 "그래프는 빼기"를 받아 ADR을 바꿀지는 열린 질문 1).
- 시행규칙·부칙 조각: `law-idx-v2`에 없다. 기한·수수료 질문에 필요해지면 새 색인 판에서 더한다.
- 판례를 분야(컴퓨터 비전)로 거르기: 판단 법리는 분야와 상관없다 (데이터 카드 3절).
- 등록공보·대상 OA 뒤 자료를 질의나 근거에 쓰기.

## 열린 질문
1. 지식 그래프: 강사님 조언("무엇을 retrieve할지와 retrieve 평가가 핵심, 지식그래프는 빼기")대로 ADR 0002의 "M3 조건부"를 "넣지 않음"으로 바꿀까? 바꾸면 ADR 0002 보완 PR과 #26·#27·#36 정리가 따른다. → 둘이 정함. 11/24 판단 기준(예: 모든 실험에서 못 찾은 CQ 몇 건이면 넣나)과 임베딩 모델 최종 목록(한국어 모델 이름, "벡터가 크게 낮음"의 기준)은 #45의 F3 PR에서 채운다.
2. 비교 실험 구현 방식 → **정함 (11/20):** 한 사람(은진)이 구현하고 설정만 바꿔 비교한다 ("비교 실험" 절).
3. 심결례: 받은 12건(컴퓨터 비전 거절결정불복)은 M2에 판례처럼 `law-idx-v3`에 넣는다. 신규성만 다룬 비전 심결은 찾지 못했다. 12건은 무료인 kipris.or.kr 웹 심판 검색(심결문 내려받기)으로 받았다. KIPRIS Plus 심판사항 상품: Open API 무료 옵션은 월 1,000건이고, 유료는 Open API 무제한 옵션과 BULK(기간제) 두 가지다 (확인: KIPRIS Plus 데이터 신청 화면 11/20, #54 댓글. 심판 API는 11/20 실제 호출 성공). 심결을 더 받을 때는 무료 Open API로 미리 받아 색인에 넣고, 실행 중에는 부르지 않는다. [확인 필요: Open API가 심결문 전문(본문·PDF)까지 주는지]. 몇 건을 어느 범위로 받을지는 열린 질문 9. 12건 안에서만 찾고, 없으면 "조회 범위 내 없음" + 찾아본 범위.
4. OA 흐름에서 발송일판과 출원일판이 다를 때: 둘 다 보이고 "확인 필요"(사람이 판단)로 할지. 진보성·신규성 요건 조문은 2019~2022년에 글이 바뀌지 않았을 가능성이 높아 드물 것으로 본다 [가정].
5. 심사기준·판례의 검색 정답: OA는 대부분 조문만 짚고 심사기준·판례는 짚지 않는다. 정답을 무엇으로 할지 (OA가 짚은 것만 / 실제 의견서가 인용한 심사기준·판례 / 사람이 고른 것) → **정함 (재아 님 11/20):** M2는 OA가 짚은 것 + 의견서가 인용한 판례를 정답으로 하고, 사람이 고르는 정답은 만들지 않는다. 정답 줄이 너무 적으면 #35에서 사람이 고른 정답을 더할지 다시 본다.
6. 판례 전문의 "판단 / 당사자 주장" 구분을 색인 때 규칙으로 할지, 답할 때 모델이 할지 → design.md 8절 [제안].
7. product.md 3.1절 표의 F2 주인 "둘" → **정함 (11/20):** 한 사람 구현을 채택했으니 "은진"으로 고치는 PR이 따른다 (10번과 같은 PR).
8. 시행규칙·부칙: product.md 8절은 F2 자료로 들지만 `law-idx-v2`에 없다. M2에서 뺄지(기한·수수료 질문만 영향) 넣을지 → 둘이 정함. 요건 조문에 어느 시점 법이 걸리는지는 보통 부칙 경과규정이라, 발송일을 기본 검색 기준일로 두는 것도 같이 본다.

"컴퓨터 비전만"은 평가할 OA 사건(product.md 7절)을 고르는 기준이라 근거 자료에는 걸지 않는다. 순서는 가까운 분야(G06) 먼저, 진보성·명확성·신규성 거절결정불복 심결을 거절이유마다 20건 안팎 무료 Open API로 미리 받고, 모자라면 넓힌다. 조각에 IPC 분야를 메타데이터로 남겨 나중에 비전 사건 먼저 보이기·거르기를 할 수 있게 한다. 받는 일과 데이터 카드는 #24 또는 따로 이슈.
10. 비교 실험 축 1 → **정함 (11/20):** `split` 기본, `single` 비교는 M3에 시간 나면. product.md 3.1 고치는 PR이 따른다 ("비교 실험" 절).
