## 무엇
법령·심사기준과 인용문헌을 같은 모양의 조각으로 저장하고, 같은 `search` 함수로 BM25·벡터 검색을 한다. 같은 채점기에 넣으면 말뭉치마다 tune 세트의 "심사관 지정 위치 회수율"(Hit@k·Recall@k)과 무작위 기준선, 못 찾은 질문(CQ 후보) 목록이 나온다.

- 법령 점수와 인용문헌 점수는 서로 비교하지 않는다. 비교는 한 말뭉치 안에서(BM25 대 벡터, 설정을 바꾼 색인 판끼리) 한다.
- 공통으로 쓰는 것: `search` 계약, 조각 표 모양, 점수 계산 틀, CQ 후보 모양.
- 말뭉치마다 다른 것: "이 조각이 정답과 맞나"를 판정하는 규칙.
- 앱에서 어느 말뭉치를 찾을지는 에이전트가 도구를 골라 정한다. 이 계약은 그 선택이 맞게 주어졌을 때 검색 도구만 잰다 ([product.md](../../product.md) 6.1 "단계마다 따로 잰다").

## 사용 장면
1. 은진 님이 #66에서 심사기준 PDF를 조각으로 잘라 법령 표에 넣는다. 그 위에서 BM25·벡터 구현을 각각 `impl`로 골라 tune 세트 법령 Hit@k를 내고 둘을 비교한다.
2. 재아가 #67에서 인용문헌을 문단(한국)·칼럼:줄(미국) 조각으로 넣는다. 거절이유 × 청구항 × 인용문헌 한 줄마다 그 인용문헌 안에서 BM25·벡터로 검색해 각각 Hit@k를 내고 비교한다.
3. 11/24에 둘이 두 말뭉치의 CQ 후보 목록을 보고 M3에 지식 그래프를 넣을지 정한다. 목록이 비었으면 채점이 고장 났는지부터 본다.

## 입력과 출력
- **입력 자료:**
  - 검색할 조각: 법령·심사기준·판례 (데이터 카드 [`docs/data/law-go-kr.md`](../../data/law-go-kr.md)), 인용문헌 원문 (데이터 카드는 #67에서 만든다). 이 이슈는 지어낸 가짜 조각만 쓴다.
  - 검색 정답: tune 세트 검색 정답 (은진 님 `tune_search_gold_1118`, git 밖 `data/goldsets/tune/`). 채점기가 읽는 정답 파일 모양은 이 이슈에서 정한다. 은진 님 파일은 #66·#67에서 변환 스크립트 하나로 맞춘다.
  - 정답 한 줄 = 거절이유 × 청구항 × 인용문헌(인용문헌 말뭉치) 또는 거절이유 × 조문(법령 말뭉치). 줄마다 아래 칸이 있다.
    - 줄 ID: 내용으로 정한다. 변환을 다시 돌려도 같은 줄은 같은 ID다.
    - 말뭉치
    - 검색 질의
    - 정답 항목 목록
    - 거를 문헌 (인용문헌 공보 번호)
    - 기준일 (법령. OA 발송일)
    - 정답 판본 (법령 판본. 변환 스크립트가 기준일로 채운다. 모르면 "확인되지 않음")
- **검색 질의:**
  - 인용문헌: OA 당시 청구항 전문(그 줄의 청구항 글자 그대로)이다.
  - 법령: 질의는 #66에서 정한다.
  - 그 줄 정답 항목의 위치 표기(예 `[0023]`, `도 3`, `29조 2항`)가 질의에 그대로 들어 있으면 정답이 새는 것이다 ([product.md](../../product.md) 6절 F3 "지정 번호를 입력에 주지 않고"). 채점기는 이런 줄이 있으면 실패로 끝난다.
  - 청구항 자신의 인용항("제1항에 있어서")과 출원 쪽 도면 부호("기판(110)")는 누출이 아니다. 테스트 fixture에 종속항 질의 하나(통과)와 누출 질의 하나(실패)를 둔다.
- **필요한 판:** 여기서 "판"은 세 가지를 나눠 쓴다. 법령 판본(시행일별 법령·심사기준), 인용문헌 공보(공개·등록), 색인 판(`index_version`).
  - 법령·심사기준 조각: 법령 판본(시행일)을 단다.
  - 인용문헌 조각: 심사관이 인용한 공보 번호(종류 코드 포함, 예 공개 `A` / 등록 `B`)를 단다. 공개공보와 등록공보는 서로 다른 공보라 문단 번호가 다를 수 있다.
  - 법령 판본을 모르는 조각에는 "확인되지 않음"을 단다.
  - 법령 정답 줄의 법령 판본은 OA 발송일에 시행 중인 판본이다. 변환 스크립트가 채우고, 모르면 "확인되지 않음"으로 둔다.
  - 색인 판 이름(`index_version`, 예 `law-idx-v1`, `cite-idx-v1`)을 조각마다 단다. 새 색인 판은 덮어쓰지 않고, 설정을 바꾼 말뭉치만 `<말뭉치>-idx-v2`로 올린다. 한 색인 판 안에 여러 법령 판본이 같이 들어간다.
- **출력:**
  - 검색 결과 = 조각 + 점수 목록. 결과 스키마 이름은 design.md에서 정한다 ([data-model.md](../../data-model.md) 4절에 아직 없음). 검색 결과는 근거 "후보"다. "확인됨"은 뒤의 출처 확인 단계가 붙인다 ([architecture.md](../../architecture.md) 8절).
  - 채점 결과 = `experiments/<실험>/scores.json`. git에 들어가므로 모은 숫자와 건수만 넣는다. 줄 ID·출원번호·질의·정답 위치는 넣지 않는다.
  - CQ 후보 목록 = git 밖 `work/retrieval/<실험>/cq_candidates.jsonl`. 정답 위치·청구항 문구가 들어가기 때문이다 ([architecture.md](../../architecture.md) 7절 "평가 정답은 git 막음").
  - 색인 덤프 = git 밖 `data/index/` ([db/CLAUDE.md](../../../src/patent_ai/db/CLAUDE.md) 검색 색인 절).
- **예시:** 가짜 조각·가짜 정답·가짜 벡터 `tests/fixtures/retrieval/` (지어낸 자료만).

## 합격 기준
1. **검색:** `search(질의, 말뭉치, mode, k, 거를 문헌, 기준일)`을 부르면 조각 + 점수가 점수 순으로 최대 k개 나온다. (필수)
   - `mode`는 `bm25` / `vector` / `hybrid`다.
   - 거를 문헌(공보 번호 목록)을 주면 그 문헌 안에서만 찾는다 (#9 B-1).
   - 기준일을 주면 그날 시행 중인 법령 판본 조각만 찾는다. 법령 판본을 모르는 조각은 기준일 검색에서 빠지고 건수가 남는다.
   - 구현은 설정 파일의 `impl`로 고른다. 없는 `impl` 이름이면 검색 전에 멈추고 쓸 수 있는 이름을 보인다.
   - `hybrid`는 이름 자리만 있고, 부르면 "지원 안 함" 오류를 낸다.
   - 결과가 0개이면 "조회 범위 내 없음"과 찾아본 범위(말뭉치·색인 판·거를 문헌·기준일)를 돌려준다.
   - 거른 문헌의 조각이 색인에 아예 없으면 "확인되지 않음(본문 미확보)"을 돌려준다.
   - 이 기준은 메모리 가짜 구현으로 테스트한다.
2. **조각 표와 덤프:** 마이그레이션을 돌리면 말뭉치마다 표 하나(법령 표, 인용문헌 표)가 생긴다. 판례는 법령 표에 넣는다. (필수)
   - 두 표의 칸은 같다: 조각 ID, 출처 문헌(인용문헌은 공보 번호), 법령 판본, 원문 위치(문단 번호 / 칼럼:줄 / 조·항·호 / 쪽), 조각 종류(본문·청구항·요약·도면 설명·조문·판결 이유 등. 값 목록은 design.md), 본문, 임베딩(길이를 정하지 않은 벡터), 색인 판 이름.
   - 법령 판본을 모르는 조각은 빈칸이 아니라 "확인되지 않음"으로 저장된다.
   - `make index-dump CORPUS=<말뭉치>`는 그 말뭉치 표 하나를 그 표의 모든 색인 판과 함께 `data/index/<말뭉치>-idx-<색인 판>.dump`(예 `law-idx-v1.dump`)로 뽑는다. 이름의 색인 판은 덤프에 든 가장 높은 색인 판이다. 명령 구현은 tasks.md에서 한다. 정본은 그 말뭉치를 만든 사람의 DB다.
   - 받는 쪽은 기존 `make index-load`로 넣는다. 상대 말뭉치 표는 바뀌지 않는다.
3. **채점 계산 (공통):** 가짜 조각·가짜 정답으로 채점기를 돌리면 설정의 k마다 Hit@k·Recall@k와 무작위 기준선이 나온다. 지표 이름은 "심사관 지정 위치 회수율"이다 (#9 B-4). (필수)
   - 정답 항목 = OA가 적은 위치 표기 하나. 범위 `[0022]-[0025]`, 도면 범위 `도 3-5`도 각각 1항목이다.
   - Hit@k(줄): 상위 k 안에 맞은 항목이 하나라도 있으면 1, 없으면 0.
   - Recall@k(줄): 맞은 항목 수 ÷ 그 줄의 정답 항목 수. 줄 안에서 항목을 빼지 않는다. 빼는 것은 아래 "점수에서 빼는 줄"뿐이다.
   - 보고값: 점수에 넣는 줄들의 평균.
   - 예: 정답 항목이 `[0022]-[0025]`, `도 3` 둘이고 상위 5개 중 `[0023]` 조각만 맞으면 Hit@5 = 1, Recall@5 = 0.5.
   - 무작위 기준선: 그 줄의 검색 범위(거를 문헌·기준일로 좁힌 조각들)에서 k개를 고르게 뽑았을 때의 기대 Recall@k다. 표본을 뽑지 않고 계산식으로 구한다 (#9 B-2).
   - 배수 = 줄 평균 Recall@k ÷ 줄 평균 무작위 Recall@k.
   - 점수에서 빼고 건수만 남기는 줄: 위치가 없는 줄, 명확성 줄(인용문헌 없음), "같은 이유: 10←1"처럼 다른 청구항을 가리키기만 한 줄, 본문 미확보 줄, 정답 판본이 "확인되지 않음"인 줄, 기준일로 거르면 검색 범위 조각이 0개인 줄(기준일 범위 내 판본 없음).
   - 실행 전에 확인하고, 하나라도 걸리면 점수를 내지 않고 실패로 끝난다:
     - 실험 설정의 `index_version`이 색인에 없거나, 검색 결과에 다른 색인 판 조각이 섞였다. 이 검사를 끄는 옵션은 없다.
     - 정답 파일이 없거나 0줄이다.
     - 질의에 정답 번호가 들어 있다.
4. **맞음 판정 (말뭉치마다):** 판정 규칙은 말뭉치마다 인터페이스 뒤에 끼운다. 공통 계산(기준 3)은 판정 규칙을 몰라도 돈다. (필수)
   - 인용문헌 판정 (#9 B-3, 이 이슈에서 만든다):
     - 공보 번호가 같아야 한다. 같은 문헌의 다른 공보에만 있으면 "확인되지 않음(본문 미확보)"이다.
     - 문단 범위 안 문단이면 맞음. 칼럼:줄 범위가 겹치면 맞음.
     - 도면·청구항·요약 항목은 그 도면 설명·청구항·요약 조각이면 맞음.
     - 같은 문헌의 다른 문단은 틀림.
   - 법령 판정:
     - 조각의 법령 판본이 정답 줄의 정답 판본과 같아야 맞음. 이 부분은 이 이슈에서 만든다.
     - 조·항·호를 세는 단위(정답이 "29조 2항"이고 조각이 "29조" 전체일 때 등)와 심사기준 위치 단위(쪽·절)는 #66이 이 자리에 끼운다.
5. **CQ 후보:** 채점기를 돌리면 설정의 가장 큰 k 안에 맞은 항목이 하나도 없는 정답 줄이 CQ 후보 파일에 자동으로 쌓인다. (필수)
   - 칸은 줄 ID, 질문(질의), 정답 위치, 찾은 것(위치·점수), 왜 못 찾았나다. "왜 못 찾았나"는 빈칸으로 두고 사람이 채운다.
   - 후보가 0건이면 경고를 남긴다.
   - 여러 실험(BM25, 벡터)의 CQ 후보를 줄 ID로 모아 모든 실험에서 못 찾은 줄만 뽑을 수 있다 (PRD "벡터·BM25로 못 찾은 질문"). 정답 파일 버전이 다른 실험끼리는 모으지 않고 멈춘다.
6. **덤프 마이그레이션 검사:** `make index-load`는 덤프를 만든 DB의 마이그레이션 revision(Alembic이 매기는 스키마 번호)과 받는 DB의 revision이 다르면 넣지 않고 멈춘다. 이게 없으면 칸이 조용히 사라질 수 있다. (있으면 좋음)
7. **실제 DB:** 실제 Postgres에서 마이그레이션이 두 표를 만들고, 색인 판·기준일로 거르는지 보는 `@pytest.mark.db` 테스트 하나. (있으면 좋음)

## 근거
- 이 기능 결과의 근거: 검색 결과 조각마다 출처 문헌(공보 번호) + 원문 위치 + 법령 판본 + 색인 판 이름. 채점 정답은 OA 통지서가 짚은 위치다. 심사관이 짚은 위치만 정답이라 "불완전한 대리 정답"이다 ([product.md](../../product.md) 6절 F3 줄).
- 앞 기능 결과가 "확인되지 않음"이면: 이 계약은 앞 기능 결과를 받지 않는다. 정답 줄의 인용문헌 원문이나 정답 판본을 확보하지 못했으면, 그 줄은 점수에서 빼고 건수로 센다 (기준 3).

## 사람이 고르거나 고치는 곳
- CQ 후보의 "왜 못 찾았나"는 사람이 채운다 (채점기는 비워 둠).
- 상위 오답 일부는 사람이 다시 본다. 심사관이 짚지 않았지만 맞는 문단일 수 있다 (#9 B-4).
- 어느 `impl`·색인 판을 채택할지는 #66·#67 실험 뒤 사람이 정한다.
- #66·#67 담당자가 이 계약(인터페이스·조각 표·공통 채점)을 고치지 않고 판정 규칙과 `impl`만 더해 쓸 수 있는지는, 이 문서와 구현 PR의 리뷰에서 상대(은진 님)가 확인한다.
