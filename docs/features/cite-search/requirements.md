## 무엇
재아(개발자)가 tune 사건 인용문헌 PDF를 원문 위치(식별번호·청구항·요약·도면 설명·쪽)가 붙은 조각으로 나눠 `cite_chunks`에 넣는다. 그 뒤 OA 당시 청구항 전문으로 그 인용문헌 안을 BM25로, 벡터(임베딩)로, 둘을 섞은 하이브리드로 검색해, 심사관이 짚은 위치를 몇 위 안에 찾는지(Hit@k) 같은 정답 줄로 견준다.

## 사용 장면
1. 재아가 F3 대비를 만들기 전에, 청구항으로 인용문헌의 근거 문단을 BM25만으로 얼마나 찾는지 기준선 숫자를 낸다. 이 숫자는 벡터·하이브리드와 그래프 검색(M3 조건부, ADR 0002)의 비교 기준이 된다.
2. 못 찾은 질문(CQ 후보)을 모아, 11/24 그래프 판단 때 "왜 못 찾았나"를 본다.
3. 재아가 F3 대비에 쓸 검색 방식(BM25 / 벡터 / 하이브리드)을 고르려고, 같은 68줄에서 세 방식의 Hit@k와 못 찾은 줄을 나란히 본다.

## 입력과 출력
- **입력 자료:** 인용문헌 PDF `data/raw/cited_v2/<출원번호>/` (데이터 카드 [`docs/data/cited-patents.md`](../../data/cited-patents.md)), OA 당시 청구항 `data/processed/cases/<출원번호>/<발송번호>/<출원번호>_청구항이력.txt` (OA 시점으로 자른 입력, #159), 검색 정답 `data/goldsets/tune/search_v0/tune_search_gold_1118_검수완료.json` (은진 님, 11/18 검수 완료).
- **외부 모델로 보내는 것 (벡터):** 인용문헌 조각 글과 OA 당시 청구항(질의)을 OpenAI 임베딩 API `text-embedding-3-small`로 보낸다 (11/20 재아). **유료 API**(단가 $0.02 / 입력 토큰 100만, OpenAI 모델 페이지(공식 문서). 조각 1,998개 기준 몇 센트 [가정: 조각당 약 300토큰으로 어림, 색인 때 호출 기록으로 잼]). [architecture.md](../../architecture.md) 7절 "공보·인용문헌 원문: 보냄". 벡터·질의 벡터 파일은 git 밖.
- **필요한 판:** 질의 = OA 당시 청구항 전문 (계약 design 7-1). 출원번호 + 발송번호로 고른다. 질의는 `청구항이력.txt`(+ OA 앞뒤를 가르는 `행정이력.txt`)에서만 만든다. 사건 폴더의 등록공보·결정서·결정본문은 채점 확인용이라 AI 입력·질의로 쓰지 않는다 (은진 님, 11/19).
- **채점 범위:** 인용문헌이 있는 tune 8건 전부 (11/19 청구항이력 8건 다 들어옴).
- **출력:** 계약의 `Chunk`(`cite_chunks`, 벡터 판은 `embedding` 칸이 찬 `cite-idx-v2`), 질의 벡터 파일(git 밖 `work/`), 계약 정답 파일 `data/goldsets/tune/retrieval/cite_gold.jsonl`, `experiments/<실험>/scores.json`, CQ 후보 목록.
- **예시:** `tests/fixtures/cite_search/` 지어낸 공보 글자·PDF만 (진짜 공보·청구항 글자는 넣지 않음).

## 합격 기준
1. 같은 설정으로 색인을 두 번 만들면 조각 ID·본문·위치가 같다 (필수)
2. 모든 조각에 문헌 번호(`doc_id`)와 원문 위치(식별번호 / 청구항 / 요약 / 도면 / 쪽)가 있다 (필수)
3. 쪽마다 되풀이되는 머리말·꼬리말·쪽 번호 줄은 조각 본문에 없고, 뺀 줄 수가 색인 보고에 있다 (필수)
4. 은진 님 정답 파일을 계약 정답 파일로 바꾸고, 질의를 못 만든 줄·위치가 없는 줄은 건수와 경고로 남긴다 (필수)
5. (AI) tune 세트 BM25 Hit@1·3·5·10과 무작위 기준선 대비 배수 한 줄 (필수). 문턱은 두지 않는다 (열린 질문)
6. 못 찾은 질문이 CQ 후보 목록에 쌓인다. 0건이면 경고 (필수)
7. 테스트는 네트워크·API 키·진짜 PDF 없이 돈다 (필수)
8. (AI) 같은 정답 줄(tune v2, BM25와 같은 n)로 벡터 Hit@1·3·5·10과 무작위 대비 배수 한 줄 (필수, 이슈 #67 합격 기준 3의 나머지)
9. (AI) 같은 정답 줄로 하이브리드(BM25 + 벡터를 RRF로 섞음) Hit@1·3·5·10과 무작위 대비 배수 한 줄 (필수, 11/20 재아가 범위에 넣음)
10. 같은 색인 판(`cite-idx-v2`)에서 세 방식(BM25·벡터·하이브리드)을 한 표로 견주고, 한국 공보 줄과 논문 줄을 나눠서도 보인다. 방식마다 CQ 건수와 "상위 10 안에서 한 방식만 찾은 줄" 수를 남긴다 (필수)
11. 벡터 색인(`cite-idx-v2`)의 조각은 판 이름 앞말만 빼면 v1과 조각 ID·본문·위치가 같고, 같은 글은 한 번만 임베딩한다. 임베딩 비용($)·호출 수가 실험 카드에 있다 (필수)
12. 벡터 칸이 빈 조각이 있거나 질의 벡터가 없으면 조용히 빼지 않고 멈춘다 (필수)

## 근거
- 정답 = OA가 짚은 인용문헌 위치 (은진 님 정답 파일). 맞음 판정은 계약 `CiteMatcher`.
- 질의 원문이 없는 사건은 채점하지 않고 건수만 남긴다 (못 찾음 ≠ 없음).

## 사람이 고르거나 고치는 곳
- 어느 `impl`·색인 판을 채택할지 (계약 requirements). 문턱 없이 세 방식 표를 보고 재아가 고른다 (11/20). 토크나이저를 바꿀지는 CQ를 본 뒤 재아가 정한다.
- 하이브리드 섞는 값(RRF `k`, 가중치)은 실험 설정 파일에 둔다. 결과를 본 뒤 다른 섞는 법을 더 찾아본다 (11/20 재아).

## 실패할 때
- PDF 글자를 못 읽음: 그 문헌을 건너뛰고 경고, 색인 보고에 문헌 번호. 채점에서는 계약대로 `excluded_body_missing`.
- 미국·그 밖 나라 문헌: "지원 안 함" 경고로 건너뜀 (이번 tune에는 없음).
- 식별번호를 하나도 못 찾은 한국 공보: 경고 (조용히 0 조각으로 끝내지 않음).
- 임베딩 호출 실패·호출 상한 넘음: 색인·질의 벡터 파일을 쓰지 않고 종료 1 (반쯤 찬 색인을 남기지 않음).
- 질의나 조각이 임베딩 모델 최대 입력(8,192토큰)을 넘음: 자르지 않고 API 오류로 멈춘다 (`embed()`는 입력을 자르지 않음). tune 질의는 최대 542자라 넘지 않는다 (11/20 잼, 105줄).
- 청구항이력이 없는 사건: 그 사건 줄을 정답 변환에서 빼고 경고 + 건수.

## 비교 실험
예. 한 사람(재아)이 구현하고 같은 계약 뒤에서 `impl`(bm25 → vector → hybrid)만 바꿔 비교한다. m2-i1 PR은 BM25 실험 폴더 1개, 다음 PR은 같은 색인 판 `cite-idx-v2`로 실험 폴더 3개 (BM25 다시 채점 `m2-i2-cite-search-bm25-v2`가 기준선, 벡터, 하이브리드).

## 안 할 것
- 리랭커, 다른 임베딩 모델 비교(3-large·로컬 모델), RRF 말고 다른 섞는 법 (결과를 본 뒤 비교 실험)
- 점수 문턱 정하기 (세 방식을 본 뒤)
- 미국 문헌 칼럼:줄 청킹, 영어 질의 (미국 문헌 없음)
- 청킹·토크나이저 비교 (CQ를 본 뒤)
- 구성요소별 질의 (F3 대비 몫)
- 계약 인터페이스·스키마 고치기 (계약 래퍼의 `hybrid` 막는 줄만 푼다. 계약 design 4절이 미리 적어 둔 길이다)
