# 2026-11-18 회의

멘토링 반영분과 AI 코어 분담.

## 정한 것
- 팀 프로젝트로 통합한다. 공유 자원(DB 마이그레이션, 검색 색인 스크립트·설정, 평가 세트, 데이터 카드, 결과 스키마)은 PR과 상대 리뷰로만 바꾼다.
- 지식 그래프: 벡터·BM25 검색을 먼저 만들고, 못 찾은 질문을 CQ(competency question)로 모은다. 11/24에 CQ를 보고 M3에 작은 그래프(인용·조문·분류코드 관계)를 넣을지 정한다. 넣으면 Neo4j. ([ADR 0002](../../decisions/0002-first-build-scope.md) 11/18 보완)
- 검색을 먼저 만든다. 둘이 검색 계약(조각 테이블 스키마, 검색 인터페이스, Hit@k 채점 스크립트)을 11/19까지 같이 정하고, 법령·심사기준 / 인용문헌 문단 검색 기준선을 한 사람씩 11/20까지 만든다 (#65, #66 법령·심사기준, #67 인용문헌).
- DB: 각자 로컬 docker compose(Postgres + pgvector)로 시작하고, 어려우면 클라우드 Postgres(Supabase)로 옮긴다. 스키마는 Alembic 마이그레이션으로만 바꾼다.
- 테스트: 답이 정해진 코드 도구와 사람 승인·누락 검사 같은 선은 촘촘히, AI 품질은 tune 점수로, 앱은 주요 API와 끝까지 한 번.
- 속도 우선: 작은 이슈는 이슈 본문 체크리스트를 구현 계획으로 본다. (CLAUDE.md 고침)
- AI 코어 분담 (담당은 이슈 Assignees):
  - OA 흐름 줄: F1과 지휘 에이전트 뼈대(M1) → 인용문헌 문단 검색 기준선 → F3 대비(M2) → F4(M3)
  - 에이전트·법률 근거 줄: 서버·데이터(M1) → 법령·심사기준 검색 기준선 → F2 법률 근거 → 근거 검토 에이전트(M2) → 평가 틀, 조건부 그래프(M3)
  - 같이: 검색 계약(#65), 지휘 에이전트 구조, 채점 기준(만든 사람이 쓰고 상대가 리뷰). 코어는 실행 함수 하나를 내놓고 API가 부른다.
  - M2에 OA 흐름 줄이 밀리면 신규성 대비(#31)나 명확성 확인(#32) 하나를 다른 줄로 옮긴다.
