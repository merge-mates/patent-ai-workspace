# 법령·심사기준·판례 (법제처 Open API) 데이터 카드

F2 법률 근거 조사에 쓰는 특허법·하위 법령, 특허·실용신안 심사기준, 판례를 법제처 Open API로 받은 것이다. 사건 OA 발송일(2019~2022년)에 맞는 판을 고를 수 있게 그 기간의 시행판을 모았다.

## 1. 출처와 이용 조건
- 어디서: 법제처 Open API (`lawSearch.do` 목록, `lawService.do` 본문). 인증키는 `.env`의 `LAW_OC`. 심사기준 원문은 각 판의 첨부파일 링크(`flDownload.do?flSeq=<번호>`, 인증키 없음).
- 이용 조건: 법령·판결·훈령·예규는 저작권법 제7조에 따라 저작권 보호 대상이 아니다. Open API 이용 약관(출처 표시)은 따로 확인하지 않았다 [가정].
- 위치: `data/raw/` (git 제외). 받은 기록은 `data/raw/DOWNLOAD_1116.md`, `data/raw/DOWNLOAD_1118.md`.
- 저장 파일 안의 인증키는 `***`로 가렸다(11/18 새 파일 100개 검사, 남은 키 0개).

## 3. 품질
- **심사기준 API 본문은 비어 있다.** `target=admrul` JSON의 `조문내용`은 안내문 한 줄뿐이고 실제 내용은 첨부 PDF·HWP에만 있다. 그래서 심사기준은 JSON이 아니라 첨부 원문을 쓴다.
- 기존 `exam_guideline_33213077.pdf`(23쪽)는 제101호 개정사항 설명자료이고 본문이 아니다.
- HWP 2판(제108·116호)은 한컴 뷰어로 PDF로 바꿔 같은 폴더에 같은 이름(.pdf)으로 두었다(HWP 원본도 남김). pdftotext로 글자가 뽑히고, 개정 연혁 마지막 예규번호가 판과 맞는 것을 확인했다. 변환본이라 쪽 번호가 원본 HWP와 다를 수 있다. 오픈소스 pyhwp(hwp5odt)는 이 파일에서 검증 오류로 실패했다.
- 판례 본문검색은 검색어를 단어로 쪼개서 찾는다. "특허법 제29조 제1항"으로 받은 첫 15건 중 8건은 신규성 사건이 아니었다(상표 사건 1건 포함). 이 8건은 파일을 두고 v2 기록에 표시만 했다.
- 신규성 15건 중 3건(2009후4285, 2006허6099, 2009후2975)은 제29조 제1항이 한 번만 나온다. 신규성이 주된 쟁점인지는 확인하지 않았다.
- 제29조 제1항이 나온 횟수만으로는 신규성 사건을 다 가리지 못한다. 진보성 판결도 "제29조 제1항 각 호의 발명으로부터…"처럼 제1항을 인용한다. 15건 중 3건(2008후3551, 2007후4977, 2006허6099)은 제29조 제2항도 함께 나온다.
- 처음 쓴 정규식은 "제129조 제1항"도 잡았다. 앞에 숫자가 없을 때만 잡도록(`(?<!\d)29조\s*제?\s*1항`) 고쳐 15건을 다시 셌고, 15건 모두 그대로 Y이고 횟수도 같았다(11/18). 저장하지 않은 N 사건은 고친 식에서 더 적게 잡히므로 바뀌지 않는다.
- 기존 심사기준 PDF 3개는 서버가 HEAD 요청에 404를 줘서 서버 파일 크기를 확인하지 못했다. 그래서 받은 기록(`exam_guideline_versions/_download_log_1118.json`)의 status가 "크기 다름"으로 남았지만, 실제 뜻은 "크기 확인 못 함"이다. 판은 표지와 개정 연혁 마지막 예규번호로 확인했다.
- 법제처 "특허" 사건 종류에는 상표·디자인·실용신안 사건도 섞여 있다. 사건명의 (상)·(디)·(실)로 거른다.
- 판례는 분야(컴퓨터 비전)로 거르지 않았다. 진보성·명확성·신규성 판단 법리는 분야와 상관없이 쓰이기 때문이다.
- 2022후11190은 법제처 DB에서 찾지 못했다(별도로 받은 hwpx·pdf가 있음).

## 4. 가공
- 받기 스크립트:
  - `scripts/fetch_exam_guidelines_versions.py`: 심사기준 옛 판 메타 JSON
  - `scripts/fetch_exam_guideline_attachments.py`: 심사기준 판별 본문 첨부(PDF 우선, 없으면 HWP)
  - `scripts/fetch_prec_novelty.py`: 신규성 판례 1차
  - `scripts/fetch_prec_novelty_refill.py`: 본문에 제29조 제1항이 있는 사건만으로 다시 채우기
  - 이 PR에 없는 것: 법령 판 받기 `fetch_law_versions.py`와 심사기준 현행 판 받기 `fetch_exam_guidelines.py`·`fetch_exam_guidelines_body.py`는 은진 로컬 `feat/law-chunker` 브랜치에만 있다(원격에 안 올림). 법령 목록·본문 받기 `list_patent_laws.py`·`fetch_law_body.py`는 원격 `feat/law-rag-demo` 브랜치에 있다. 진보성·명확성 판례(11/16)는 스크립트로 남지 않았고, 받은 방법은 `data/raw/DOWNLOAD_1116.md` 1절에 있다.
  - 캐시·호출 상한 예외는 CLAUDE.md 코드 규칙을 따른다 (이 스크립트들은 이미 있는 파일이면 멈추고 호출 사이 1초 쉰다).
- 모든 스크립트는 기존 파일을 덮어쓰지 않고 멈추며, 호출 사이 1초 쉰다.
- raw → processed(조각 테이블·청킹·임베딩)는 이슈 #65(검색 계약)와 이슈 #66에서 정한다.
- 법령 색인 `law-idx-v1` (#66, 11/19): `data/raw/law/body_<법령>_<MST>_<시행일>.json` → `uv run python -m patent_ai.retrieval.law_index --config config/index/law-idx-v1.yaml` → `data/processed/law/law-idx-v1.jsonl`.
  - 범위: 특허법 14판 + 시행령 3판 조문만(시행규칙은 설정 `laws`에서 뺌). 조각 10,649개, 판본 모름 0개. 같은 입력이면 같은 바이트.
  - 버리는 것: 장·절 제목(`조문여부=전문`), 삭제된 조·항·호(글이 "삭제"뿐), `<개정 …>`처럼 날짜가 든 꺾쇠 꼬리표.
  - 원본 모양 주의: `항`이 목록이 아니라 하나(dict)이거나 `항번호` 없이 `호`만 있는 조가 있고(항 0 조각), `목내용`이 겹목록인 곳이 있다(시행령 제7조).
  - DB: `uv run python -m patent_ai.retrieval.law_index_db --jsonl … --index-version law-idx-v1` → `make index-dump CORPUS=law`.
- 법령 색인 `law-idx-v2` (#66, 11/19): `law-idx-v1.jsonl` → `uv run --env-file <.env> python -m patent_ai.core.index_embed chunks --config config/index/law-idx-v2.yaml` → `data/processed/law/law-idx-v2.jsonl` (약 320MB).
  - v1과 조각·글·위치·판본이 같고 `embedding`(text-embedding-3-small, 1536차원)만 더함. 고유 글 1,142개만 보냄 (입력 토큰 201,250, $0.0040).
  - 덤프 `law-idx-v2.dump`(약 73MB)에는 v1·v2가 같이 들어간다 (`.fingerprint.json`에 판마다 지문).

## 5. 쓰면 안 되는 곳
- 저장소에 원문(조문·판결문·심사기준 본문)을 넣지 않는다. 이 카드에는 건수와 필드 이름만 둔다.
- 판본을 모르는 근거를 "확인됨"으로 내지 않는다. 사건 OA 발송일에 맞는 판이 없으면 "확인되지 않음"이다.
- 평가 세트(`data/goldsets/`)의 정답을 만드는 데 쓰지 않는다.
