# 용어집

PRD·기획서·기능 문서에서 쓰는 용어. 특허 용어는 특허법·심사기준 표준 용어를 쓴다. 개발 용어는 현업에서 부르는 그대로 쓴다(원래 영어로 부르면 영어로). 팀이 따로 지은 말은 쓰지 않는다. 새 용어는 여기에 더한다.

## 특허·평가 용어

| 용어 | 뜻 |
|---|---|
| OA (의견제출통지서) | 심사관이 거절이유를 알리고 의견서·보정서를 낼 기회를 주는 문서 |
| 최초거절이유통지 / 최후거절이유통지 | 첫 거절이유통지와, 보정으로 새로 생긴 거절이유에 대한 통지. 최후거절이유통지 뒤에는 보정 범위가 47조 3항으로 제한된다 |
| OA 당시 청구항 | 심사관이 그 OA를 쓸 때 본 청구항 판. 공개·등록 청구항과 다를 수 있다 |
| OA 시점 자르기 | 사건 자료를 대상 OA(발송번호)와 그 앞 이벤트까지만 넣는 것. 이력 순서·발송번호·접수번호로 자르고 날짜만으로 자르지 않는다. 대상 OA 뒤의 보정서·청구항 판·등록공보 청구항은 넣지 않는다. OA마다 선이 다르다 |
| 인용발명 / 인용문헌 / 식별번호 | 심사관이 거절 근거로 든 선행기술 / 그것이 실린 문헌 / 명세서 문단 번호([0023] 등). OA는 인용문헌의 식별번호를 짚는다 |
| 의견서 / 보정서 | OA에 반박하는 글 / 청구항·명세서를 고치는 서류 |
| 판본 / 부칙 | 법령·심사기준의 시행일별 판(국가법령정보센터의 '연혁법령') / 법령 끝의 시행일·경과 규정 (옛 사건에 어느 판을 쓰는지 정함) |
| 신규성·진보성 / 기재불비 | 인용발명과 대비해 판단하는 특허요건 거절이유(29조) / 청구범위·발명의 설명 기재요건 거절이유(42조, 예: 명확성) |
| 독립항 묶음 | 독립항 하나와 그 독립항을 인용하는 종속항들 (명확성은 청구항 하나). F3 대비와 반박 논점을 처음 분석할 때 보는 틀(판단 단위)이다. 보정은 묶음마다 정하지 않고 사건 전체에서 한 번 정한다(사건 단위 보정안): 묶음 단위로 정하면 종속항만 바뀌는 보정을 놓친다. 화면에서는 '묶음 N' 대신 청구항 범위로 부른다. |
| 확신도 | AI가 대응 방향 순위에 붙이는 확신 단계: 높음 / 중간 / 낮음 |
| 직접 판단 필요 | 확신도가 낮아 AI가 순위를 매기지 않고 사람에게 넘긴 묶음. 사람이 고를 때까지 그 묶음 초안은 보류 |
| 사건 그룹 | 평가 사건을 OA의 거절이유 조합으로 나눈 그룹: 진보성만 / 명확성만 / 지원 이유끼리 섞임(신규성 포함·없음) / 지원 안 하는 이유 섞임 |
| 실제와의 일치율 | AI 결과가 실제 변리사의 의견서·보정서와 맞는 비율. 다른 방향도 맞을 수 있어 "정답률"이라 부르지 않는다 |
| oracle 평가 | 앞 단계에 정답(예: 실제 방향)을 넣고 그 단계만 따로 재는 평가 |
| 심사관 힌트 | OA의 「특허 가능한 청구항」 목록과 【보정에 관한 참고사항】 항목. 에이전트가 읽고 대응 방향에 쓴다 |
| 실제 방향 | 실제 변리사가 낸 보정서·의견서에서 뽑은 대응 방향. 방향 평가의 정답 |
| 지식 그래프 / 그래프 검색 | 인용·조문·분류·거절이유·청구항 요소–문단 사이 관계 / 그 관계를 1~2단계 따라가 후보와 가져온 이유를 찾는 검색 |
| 단계 검증 | 대비 뒤, 법률 근거 뒤, 초안 뒤처럼 중요한 단계마다 결과를 다시 확인하는 것 |
| tune / report 세트 | 개발 중 보는 평가 세트 / M3 끝(11/26)에 한 번만 쓰는 평가 세트 |

## 개발 용어

표준 뜻에 출처가 있으면 출처와 출처 종류(학회 논문 / 공식 문서 / 오픈소스 등)를 붙인다. "이 프로젝트에서"는 우리 쓰임이 표준과 다르거나 꼭 알아야 할 것만 한 줄로 쓴다 (이슈 #174).

| 용어 | 표준 뜻 (출처) | 이 프로젝트에서 |
|---|---|---|
| chunk | 검색·RAG에서 문서를 잘라 만든, 검색해서 가져오는 단위 텍스트 (Lewis 외 2020 RAG 논문, NeurIPS, 학회 논문 — 문서를 100단어 passage로 나눠 검색) | 문단·조·항 단위. 원문 위치·판본을 같이 둔다 |
| corpus | 검색 대상이 되는 문서 모음 | `law`(법령·심사기준·판례), `cite`(인용문헌) 두 개. corpus마다 테이블 하나 |
| index | 검색을 빠르게 하려고 corpus에서 미리 만든 자료 구조. 키워드 검색은 inverted index(역색인), 벡터 검색은 ANN index(예: HNSW, IVFFlat) (pgvector README, 오픈소스) | BM25 inverted index는 검색할 때마다 메모리에 만들고 저장하지 않는다. 벡터는 ANN index 없이 exact search (`retrieval/design.md` 결정 표) |
| `index_version` | (표준 용어 아님) | 같은 설정(청킹·임베딩 모델)으로 만든 chunk 묶음의 버전 이름(`law-idx-v1`). 표준 뜻의 index가 아니다. 설정을 바꾸면 새 버전. "판본"(법령 시행일별 판)과 다르다 |
| dump | DB 내용을 파일로 뽑아 둔 것. 다시 불러올 수 있다 (PostgreSQL 공식 문서 `pg_dump`) | `make index-dump` |
| fingerprint | 내용이 같은지 가리려고 내용에서 계산한 짧은 해시 값 | `.fingerprint.json`: 버전마다 chunk 수와 `chunk_id` 목록의 sha256 |
| Recall@k | 정답 중 상위 k개 결과 안에 든 비율 | 정답 = 심사관이 OA에서 짚은 위치뿐이라, 안 짚었지만 맞는 문단은 틀림으로 센다 |
| Hit@k | 상위 k개 결과 안에 정답이 하나라도 있으면 1, 없으면 0인 지표 | 위와 같은 정답 기준 |
| baseline | 비교의 기준이 되는 단순한 방법과 그 점수 | |
| recorded response (기록된 모델 응답) | 테스트에서 외부 호출을 실제로 하지 않으려고, 한 번 받은 응답을 파일로 저장해 두고 다시 읽는 방식(record/replay)의 그 파일 (VCR.py 문서 "cassette", 오픈소스) | 모델 응답은 `scripts/record_llm.py`가 만든다. 외부 API 응답도 같은 방식으로 저장한 파일로 테스트 (`CLAUDE.md` 코드 규칙) |
| fake response (가짜 응답) | 테스트에서 사람이 FakeTransport에 직접 써 둔 답. 실제 모델이 낸 답이 아니다 (출처 없음, 팀 정의) | |
| CQ (competency question) | 지식 그래프·온톨로지가 답할 수 있어야 하는 질문 목록. 설계와 평가 기준으로 쓴다 (Grüninger & Fox 1995, IJCAI-95 온톨로지 워크숍, 학회 논문) | 검색이 정답 위치를 못 찾은 질문을 모은 것. 그래프를 넣을지 정하는 재료. 표준 뜻보다 좁게 쓴다 |
| long-context input | 문서를 chunk로 나눠 검색하지 않고 전체를 모델 컨텍스트에 넣는 방식 | 예전 "통째로 넣기", "전문 입력" |
| scorer | 결과와 정답을 비교해 점수를 내는 평가 코드 (Inspect AI 문서 "Scorers", 오픈소스) | `eval/` |
| LLM-as-a-Judge / judge model | LLM이 기준(루브릭)에 따라 다른 모델 결과를 채점하는 방식 / 그 채점 모델 (Zheng 외 2023 "Judging LLM-as-a-Judge with MT-Bench and Chatbot Arena", NeurIPS, 학회 논문) | |
| page text | PDF에서 페이지마다 뽑은 텍스트 (pdfplumber `Page.extract_text()`, 오픈소스) | 청킹과 F1 입력의 재료 |
| header / footer | 문서 페이지마다 위·아래에 되풀이되는 줄 | 공보의 공보 번호·페이지 번호 줄. 청킹 전에 뺀다. 발명의 명칭이나 "발명의 설명" 같은 소제목과 다르다 |
| 도면 설명 chunk | (특허 용어 "도면의 간단한 설명" + chunk) | 도면 하나를 설명하는 한 줄로 만든 chunk. 본문 식별번호 chunk가 "도 3"을 말하는 것과 다르다 |

## 예전 이름 (옛 문서를 읽을 때)
팀이 따로 지어 쓰던 말을 현업 용어로 바꿨다 (이슈 #174). 옛 문서·커밋에서 왼쪽 말을 보면 오른쪽 뜻이다.

| 예전 이름 | 지금 용어 |
|---|---|
| 조각 | chunk |
| 말뭉치 | corpus |
| 색인 | index |
| 색인 판 | `index_version` |
| 지문 (색인 지문) | fingerprint |
| 회수율, 심사관 지정 위치 회수율 | Recall@k, Hit@k |
| 기준선 | baseline |
| 녹화 응답 | recorded response (기록된 모델 응답) |
| 쪽 글자, 쪽 텍스트 | page text |
| 머리말·꼬리말 (공보) | header / footer |
| 통째로 넣기, 전문(全文) 입력 | long-context input |
| LLM 저지 | LLM-as-a-Judge (모델은 judge model) |
| 칸 | DB는 컬럼, 스키마·API는 필드, 문서는 절·항목 |

기획서 전체 용어는 [기획서 16절](../service_plan_v3.1.md#16-용어).
