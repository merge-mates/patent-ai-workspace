## 진보성 — 심사관·법원이 따지는 순서

요약: 통상의 기술자가 선행기술로부터 청구항에 기재된 발명을 쉽게 발명할 수 있었는지를 본다. 발명의 내용을 알고 난 뒤 거꾸로 맞추어 판단(사후적 고찰)해서는 안 된다.

| 내용 | 출처 | 종류 |
|---|---|---|
| 순서: ① 선행기술의 범위·내용 ② 청구항에 기재된 발명과 선행기술의 차이 ③ 출원 당시 통상의 기술자 수준 → 차이를 쉽게 극복할 수 있었나 | 대법원 2009.11.12. 선고 2007후3660, [대법원 2026.1.29. 선고 2022후11190](https://www.scourt.go.kr/sjudge/1770104892901_164812.pdf) | 판례(공식) |
| "명세서에 개시되어 있는 기술을 알고 있음을 전제로 하여 사후적으로 ... 판단해서는 안 된다" (사후적 고찰 금지) | 대법원 2007후3660 | 판례(공식) |
| 여러 문헌을 합칠 때: 문헌에 결합의 암시·동기가 있거나, 기술상식·기본 과제·발전 경향·업계 요구로 보아 쉽게 결합할 수 있으면 진보성 부정 | [대법원 2022후11190](https://www.scourt.go.kr/sjudge/1770104892901_164812.pdf) | 판례(공식) |
| 청구항 중 **하나라도** 거절이유가 있으면 출원 전체가 거절된다 | 위와 같음 | 판례(공식) |
| 의견제출 기회를 주지 않은 거절이유는 소송에서 새로 주장할 수 없다. 이미 통지한 거절이유를 보충하는 자료는 쓸 수 있다 | 위와 같음 | 판례(공식) |
| 실무 반박 논리: 구성 결합의 곤란성, 예측되지 않은 효과. 실험 데이터가 있으면 더 효과적. 진보성은 보정+의견서가 함께 필요한 경우가 많다 | 2026-03-22 | 회사(사무소) 블로그 |
| 명세서에 효과와 구성의 인과관계를 구체적으로 적어 두면 진보성 판단이 달라질 수 있다 | 2026-08-11 | 회사(사무소) 블로그 |
| 검토 순서: 기존 청구항 → 심사관 선행기술 → 차별되는 핵심 구성 → 유지해야 할 권리범위. "등록 이후에도 의미 있는 권리를 남기는 것"이 핵심 | 2026-10-02 | 회사(사무소) 블로그 |

- "저해요인(선행문헌이 오히려 그 결합을 말린다)"도 흔히 쓰는 반박이라고 알려져 있지만, 이번 조사에서 출처를 찾지 못했다. (추론, 확인 필요)

### 진보성 — 구성 전체와 효과
| 내용 | 출처 | 종류 |
|---|---|---|
| 여러 구성을 합친 발명은 구성 하나하나가 아니라 "유기적으로 결합된 전체로서의 구성의 곤란성"을 보고, 결합된 전체의 "특유한 효과도 함께 고려"한다 | 대법원 2021.4.8. 선고 2019후10609 | 판례(공식) |
| 효과가 선행발명보다 현저하면 구성의 곤란성을 추론하는 유력한 자료. 곤란성이 불분명해도 "이질적이거나 양적으로 현저한 효과"가 있으면 진보성이 부정되지 않는다 | 위와 같음 | 판례(공식) |
| 차이점을 여러 선행발명과 결합해도 극복하기 쉽지 않다고 본 사례 (주 선행발명 + 보조 선행발명 구조) | [대법원 2025.7.16. 선고 2022후10524](https://www.scourt.go.kr/sjudge/1753062638667_105038.pdf) | 판례(공식) |
| 진보성 부정 논리는 주로 ① 청구항이 너무 넓어 선행기술과 겹칠 때 ② 현저한 효과가 데이터로 명세서에 없을 때에 몰린다 | 2026-06-26 | 개인 글(전문가 기고) |
| "저해요인"은 2019후10609 판결요지에 용어로는 안 나오고 본문에만 나온다 | 위 판결 | 판례(공식) — 공식 정의는 심사기준 확인 필요 |
