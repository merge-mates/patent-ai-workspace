# F1 통지서 읽기 정답 형식 (제안)

- 상태: 확정 (#90, 11/18 재아 승인). #9 정답 규칙에 합친다.
- 근거: tune 10건 의견제출통지서(OA)로 초안을 만들면서 정함 (11/18). 합격 기준은 [product.md](../product.md) 5절 F1, 칸 모양은 [data-model.md](../data-model.md) 4절 ① `OAResult`.
- 채점 단위: 청구항마다 (#9 A안). 필드별 추출 정확도로 잰다 (product.md 6절).

## 1. 무엇을 보고 만드나
- OA PDF 본문만 본다. 의견서·보정서·결정서·등록공보는 보지 않는다.
- 통지 종류도 원문만으로 정한다 (2.1). 행정이력은 검수 메모(`basis`)로만 남긴다.
- 쪽은 OA PDF 쪽(1부터). OA 아래에 찍힌 쪽 번호와 같다.
- 정답 파일은 git 밖 `data/goldsets/tune/f1/`에 OA 한 통에 하나 (`<출원번호>_<발송번호>.json`). 저장소에는 출원번호·원문을 넣지 않는다. 아래 예시는 만든 값이다.

## 2. 칸
OA 한 통 = 기본 필드 + 거절이유 표 + 인용문헌 표 + 청구항 줄.

### 2.1 기본 필드
값 하나는 `{값, 원문 글자, 쪽}`. 날짜는 원문 글자 그대로 두고 자동 확정하지 않는다 (F1 합격 기준 2).

| 필드 | 예시 (원문 글자) | 애매한 경우 |
|---|---|---|
| 출원번호 | `10-2099-0000001` | |
| 발송번호 | `9-5-2099-000000001` | |
| 통지일 | `2099.01.26.` (원문 "발송일자") | |
| 제출기일 | `2099.03.26.` | |
| 통지 종류 | `최초거절이유통지` (코드 `initial`) | "최초"는 첫 번째 OA라는 뜻이 아니라 최후가 아닌 통지(47조 1항)라서 이름 전체로 적는다. KIPO는 최후 통지에만 "최후거절이유통지" 표시를 붙이므로 원문에 표시가 없으면 `최초` (F1 합격 기준 6: 원문에서 읽음). 원문이 잘려 머리말을 못 보면 `확인되지 않음` |
| 심사 대상 청구항 | `제1-20항` → [1..20] | |
| 특허 가능한 청구항 | `제1-4, 6-20항` | 칸이 없으면 `없음` (`확인되지 않음`과 다름) |
| 보정에 관한 참고사항 | 원문 문장 그대로 | 원문 제목이 "보정서 제출시 참고사항"이어도 같은 칸. 없으면 `없음` |

### 2.2 거절이유 표
OA "거절이유가 있는 부분과 관련 법조항" 표의 순번마다 한 줄.

| 칸 | 값 |
|---|---|
| 순번 | OA 순번 |
| 종류 | `진보성`(29조②) / `신규성`(29조①1호·2호) / `명확성`(42조④2호) / 그 밖은 조문 이름 (예: `청구항 기재방법`, `배경기술 기재`) |
| 조문 | 원문 글자 그대로 (예: `특허법 제42조제8항 및 특허법 시행령 제5조제6항`) |
| 지원 | 세 종류면 `예`, 아니면 `지원 안 함` (화면에서 "직접 검토 필요", F1 합격 기준 5) |
| 대상 | 원문 글자 (예: `청구항 제1항 내지 제4항, 제8항 내지 제13항, 제17항`) + 펼친 번호. `청구항 전항`은 심사 대상 청구항 전부로 펼친다 |
| 쪽 | 표가 있는 쪽 (본문이 이어지는 쪽은 따로 적어도 됨) |

- 청구항이 아닌 곳이 대상인 이유(예: 발명의 설명 배경기술)는 이 표에만 두고 청구항 줄을 만들지 않는다.

### 2.3 인용문헌 표
| 칸 | 값 |
|---|---|
| 라벨 | OA에 나온 순서대로 `D1`, `D2` (OA "인용발명 1"과 같은 번호) |
| 원문 표기 | 원문 그대로 (예: `공개특허공보 제10-2099-0000001호(2099.12.23.)`) |
| 키 | 맞춰 볼 키. 한국 공개 `KR20990000001A`, 한국 등록 `KR109900001B1`(제10-9900001호). 미국 등록 `US1234567B2`, 미국 공개 `US20200123456A1`, 일본 `JP2020123456A`. 논문은 `NPL: <제목 줄임> (<학회 연도>)`. 종류 코드는 원문에 있으면 그대로 쓴다. 없으면 미국 공개(연도+7자리)는 `A1`, 미국 등록은 코드 없이(`US1234567`, B1·B2는 번호로 못 가림) 적는다. 채점은 나라+번호로 하고 종류 코드는 보지 않는다. F1 키로 검색 조각을 찾을 때의 번호 맞추기는 #67 정규화를 따른다 (11/19 은진) |
| 쓰인 거절이유 | 순번 목록 |
| 쪽 | 처음 나온 쪽 |

### 2.4 청구항 줄 (채점 단위)
한 줄 = 청구항 × 거절이유. 청구항 하나에 이유가 여럿이면 줄도 여럿 (F1 합격 기준 3). 거절이유 없는 청구항은 줄을 만들지 않는다.

| 칸 | 값 | 예시 |
|---|---|---|
| 청구항 | OA 시점 번호 | `12` |
| 종류·조문 | 2.2와 같은 값 | `진보성`, `29조②` |
| 인용 | 그 청구항에 쓴 인용문헌. 결합이면 `D1+D2`. 판단 문장에 인용발명이 없으면 3절 12번 | `D1+D2` |
| 짚은 위치 | 인용문헌마다 OA가 짚은 위치. 문단은 4자리(`[0016]`), 범위는 `[0080]-[0081]` 하나로 쓴다(`[0080-0081]` 꼴 안 씀, 검색 정답도 같은 꼴). 도면 `도 4c`, 인용문헌 청구항 `청구항 9`, `요약`. 미국 문헌 칼럼·줄은 `3:5-10`(col. 3, ll. 5-10). 논문은 원문대로 `3쪽 3.1절 1-5줄` | `D1: [0014], [0056], 도 4b / D2: 청구항 1` |
| 명확성 문제 표현 | 명확성 줄은 인용 대신 OA가 짚은 표현(따옴표 안 글자). 채점: 공백·따옴표를 지운 뒤 한쪽이 다른 쪽에 들어 있으면 맞음. 이유 한 구는 참고용(채점 안 함) | 표현 `상기 프리뷰 이미지`, 이유 `앞에 정의 없음` |
| 같은 취지 | 자기 위치 없이 다른 청구항·다른 거절이유를 가리키기만 하면 그 대상. JSON은 `claim:<번호>` / `rejection:<순번>`의 목록 | `["claim:1"]`, `["rejection:2"]` |
| 쪽 | 그 청구항 판단이 적힌 쪽. 두 쪽에 걸치면 시작~끝 쪽. JSON은 `page`(시작)와 걸칠 때만 `page_end`. 채점: 앱 쪽이 그 범위 안이면 맞음 (11/19 은진) | `4-5` |

## 3. 애매한 경우 (tune 10건에서 나온 것)
1. **같은 취지**: "제20항은 제1항과 동일한 취지의 거절이유" 같은 줄은 위치 칸을 비우고 같은 취지 칸만 채운다. 위치 채점에서 빼고 "가리킨 대상이 맞나"만 본다 (검색 정답 규칙 #9 B-3과 같음).
2. **짝을 안 지어 준 같은 취지**: "청구항 8 내지 10은 청구항 1 내지 3과 같다"처럼 하나씩 대응을 안 적으면 묶음을 펼친 목록 `["claim:1", "claim:2", "claim:3"]`. 그중 하나만 맞아도 맞음.
3. **자기 위치 + 같은 취지 둘 다**: "청구항 1, 2는 거절이유 2와 같고, 한편 청구항 1은 [0043]…"이면 두 칸 다 채운다.
4. **위치 없음**: "단순 부가", "설계 사항"처럼 인용 위치가 없으면 `위치 없음 (<OA 표현>)`. 검색 채점에서 뺀다. 그 표현이 가리키는 인용 아래에 적는다 (tune 2줄, 둘 다 인용이 하나인 줄). 인용이 여럿인 줄(`D1+D2`)은 OA가 위치를 짚은 인용에만 위치를 적고, 짚지 않은 인용은 `locations`에 넣지 않는다 (tune 16줄). 인용이 여럿인데 `위치 없음`이 어느 인용 것인지 원문에 없는 줄은 tune에 없다.
5. **도면 부호만**: "폐곡선(310, 320)"처럼 문단 없이 부호만 짚으면 부호를 그대로 적는다.
6. **문단 번호 꼴**: OA가 `[16, 38, 78]`처럼 적어도 `[0016], [0038], [0078]`로 맞춘다.
7. **결합 진보성**: OA가 "인용발명 1 내지 2의 결합"이라 하고 위치는 D1만 짚었으면 인용은 `D1+D2`, 위치는 D1만.
8. **신규성·진보성 같은 청구항**: 진보성 쪽에서 "1-1에서 본 바와 같이"로만 적으면 진보성 줄은 같은 취지 `["rejection:1"]`.
9. **지원 안 하는 이유**: 거절이유 표에는 넣고 `지원 안 함`. 그 청구항의 다른 지원 이유 줄은 그대로 채점한다.
10. **묶어서 짚은 청구항**: OA가 "제5-7항 발명에서 한정하고 있는 기술적 특징은 … ([0069])"처럼 여러 청구항을 한 번에 짚으면 5·6·7항 줄에 같은 위치를 하나씩 다 준다 (11/18 은진).
11. **따옴표 없는 명확성**: OA가 문제 표현을 따옴표로 짚지 않으면(예: "모듈들은 장치 구성을 특정할 수 없다") `clarity_terms`는 빈 목록이고, 그 줄은 "그 청구항에 명확성 거절이 있다"만 맞으면 맞음 (11/18 은진).
12. **인용발명이 안 적힌 줄의 인용**: 판단 문장에 인용발명이 적혀 있으면 그 문헌, 없고 같은 취지면 그 대상 줄의 인용(대상이 `claim:N`이면 같은 거절이유의 청구항 N 줄, `rejection:N`이면 같은 청구항의 거절이유 N 줄. 대상이 여럿이면 그 인용을 합친다), 둘 다 아니면 그 거절이유에 쓰인 인용 전부. 앱도 이 순서로 정한다 (모델이 고르지 않음). tune 101줄 중 98줄이 "그 거절이유 인용 전부"와 같다 (11/19 은진).

## 4. JSON 모양 (채점기 #20이 읽는 것)
```json
{
  "gold_version": 1,
  "source": "oa_pdf",
  "reviewed": {"by": null, "date": null},
  "application_number": {"value": "1020990000001", "text": "10-2099-0000001", "page": 1},
  "dispatch_number": {"value": "952099000000001", "text": "9-5-2099-000000001", "page": 1},
  "notice_date": {"text": "2099.01.26.", "page": 1},
  "response_due": {"text": "2099.03.26.", "page": 1},
  "notice_kind": {"value": "initial", "text": null, "page": null, "basis": "최후 표시 없음 (없어서 판단)"},
  "examined_claims": {"value": [1, 2, 3], "text": "제1-3항", "page": 1},
  "allowable_claims": {"value": [], "text": null, "page": null, "basis": "원문에 칸 없음"},
  "amendment_note": {"value": null, "text": null, "page": null, "basis": "원문에 칸 없음"},
  "rejections": [
    {"no": 1, "kind": "inventive_step", "article": "특허법 제29조제2항", "supported": true,
     "targets": {"value": [1, 2, 3], "text": "청구항 제1항 내지 제3항"}, "page": 1}
  ],
  "citations": [
    {"label": "D1", "text": "공개특허공보 제10-2099-0000001호(2099.12.23.)", "key": "KR20990000001A", "rejections": [1], "page": 2}
  ],
  "claim_rows": [
    {"claim": 1, "rejection": 1, "citations": ["D1"],
     "locations": {"D1": ["[0014]", "[0080]-[0081]", "도 4b"]}, "same_as": [], "page": 3, "page_end": 4},
    {"claim": 3, "rejection": 1, "citations": ["D1"], "locations": {}, "same_as": ["claim:1"], "page": 3}
  ]
}
```
- `kind` 코드: `novelty` / `inventive_step` / `clarity` / `other`. 지원 여부는 `supported`, 어떤 이유인지는 `article`로 본다. 이름은 결과 스키마 코드(#14)와 맞춘다.
- 명확성 줄은 `locations` 대신 `clarity_terms: ["상기 프리뷰 이미지"]`, 참고용 `clarity_reason: "앞에 정의 없음"`.
- `gold_version`은 정수이고 `data/goldsets/VERSION`(정수)과 같아야 하며, 다르면 채점기가 멈춘다 (`.claude/rules/eval.md`, #20). 지금 판 `1`은 #20 첫 점수 전까지 칸 추가·원문 글자 고침을 같은 판으로 둔다. 첫 점수가 나온 뒤에는 정답을 고칠 때마다 판을 올린다 (점수 비교가 어느 판 기준인지 남게).
- 고를 수 있는 칸: 청구항 줄 `page_end`(판단이 다음 쪽까지 이어질 때 끝 쪽, 2.4 쪽 칸), `notice_kind.label`(통지 이름 전체, 예 `최초거절이유통지`), `reviewed.method`·`reviewed.scope`(검수 방법·범위). 이 밖의 칸은 형식 검사(`eval/f1/gold.py`)가 막는다.
- 문단 표기는 `[0016]`·`[0080]-[0081]`만 받는다. 도면·청구항·요약·칼럼·논문·도면 부호 꼴은 2.4·3절대로 원문에 맞춰 적는다.
- `OAResult`의 "심사관 논리 요지"는 F1 합격 기준 밖이라 정답에 넣지 않고 채점하지 않는다.
- `notice_kind`: `initial` / `final` / `unknown`.
- 원문에 글자가 없어서 정한 값(통지 종류 `최초`, 특허 가능한 청구항·보정 참고사항 `없음`)은 `page: null`이고 `basis`에 그 이유를 적는다. 1쪽 머리말·거절이유 표 아래·[첨 부] 앞을 다 봤는데 없다는 뜻이다.

## 5. 정한 것 (11/18 재아 리뷰)
1. 통지 종류는 원문만으로: 표시 없음 → `최초`.
2. 없는 칸(특허 가능한 청구항, 보정 참고사항)은 `없음`으로 두고 채점한다 (AI가 지어내면 틀림).
3. 같은 취지 줄은 위치 채점에서 뺀다.
4. 명확성 줄은 문제 표현 겹침으로 채점한다 (2.4 정의).
5. 정답 파일은 `data/goldsets/tune/f1/`. 드라이브 사본 위치는 #9에서 평가 목록 위치와 같이 정한다.
