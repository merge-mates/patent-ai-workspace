# 인터뷰: $ARGUMENTS

목표: 사람이 머릿속에만 가진 결정을 문서로 꺼낸다. 질문은 한 번에 하나, 가장 모호한 것부터. 사람에게는 결정만 묻는다.

## 장치 네 개 (deep-interview, grill-with-docs에서 가져온 것)
1. **모호함 점수** (끝내는 기준): 아래 네 칸을 0~1로 매기고 매 질문 뒤 다시 매긴다. 넷 다 0.2 이하가 되면 끝낸다.
   - 목표(무엇을 왜) / 범위(안 할 것) / 합격 기준(숫자·예시) / 제약(시간·비용·데이터·API 상한)
2. **가장 약한 칸 먼저**: 점수가 가장 높은(가장 모호한) 칸에서 질문 하나를 고른다.
3. **반대로 묻기**: 세 번째 질문마다 "이걸 안 하면 무엇이 깨지나?" 또는 "반대로 하면?"을 묻는다. 당연해 보이는 가정을 흔든다.
4. **용어 짚기**: 애매한 말이나 두 뜻으로 읽히는 말이 나오면 바로 짚어 묻는다. 정하면 `docs/product/domain/용어집.md`에 한 줄 쓴다. 파일이 없으면 만든다. 표 모양: `| 용어 | 뜻 | 헷갈리는 말 | 정한 날 |`.

## 하는 법
1. 먼저 읽는다: `docs/product.md`, (있으면) `docs/features/<기능>/requirements.md`, `docs/assumptions.md`, `docs/product/domain/용어집.md`.
2. 이미 문서에 답이 있는 것은 묻지 않는다. 읽은 것으로 점수를 먼저 매긴다.
3. 사실(기존 코드, 외부 API, 라이브러리, 문서에 이미 있는 것)은 사람에게 묻지 않는다. **researcher 에이전트**를 불러 찾는다. 사람에게는 결정만 묻는다.
4. 질문은 **AskUserQuestion 도구**로 한 번에 하나 낸다. 보기는 3개. 첫 보기가 추천이고 이름 끝에 "(추천)"을 붙이고 설명에 이유를 한 줄 쓴다. 나머지 보기에도 무엇이 달라지는지 한 줄. "기타" 입력은 도구가 붙여 준다.
5. requirements 인터뷰에서는 **사용 장면**(누가·어떤 상황에서·무엇을 하려고)과, 합격 기준마다 **필수 / 있으면 좋음**을 묻는다.
6. 사람이 "몰라", "나중에"라고 하면 일단 정한 값이 있을 때 `docs/assumptions.md`에 `[가정]` 줄로 남기고 넘어간다 (언제 잴지 한 줄). 값을 정하지 못했으면 문서에 `[확인 필요: 무엇]`으로 남긴다.
7. 결과는 제안만 하지 않고 문서에 바로 쓴다. 단 `main`이 아닌 문서 브랜치(`docs/<이슈번호>-<짧은설명>`)에서 쓴다. 지금 브랜치가 `main`이면 멈추고 브랜치를 만들자고 제안한다. 합의는 PR 리뷰로 한다.
8. 인터뷰가 끝나면 대상 문서(`requirements.md` 또는 `design.md`)를 `docs/features/_template/`의 틀로 만들거나 고쳐 쓴다. 틀의 칸을 다 채우고, 정하지 못한 것은 `[가정]` 또는 `[확인 필요: 무엇]`으로 남긴다. 다 쓰면 `/doc-review`를 하자고 말한다.
9. ADR은 세 조건이 다 맞을 때만 `docs/decisions/`에 `상태: 제안`으로 쓴다: 되돌리기 어렵다 / 이유를 모르면 이상해 보인다 / 진짜 선택지가 있었다. 하나라도 아니면 그 기능 `design.md`의 결정 칸에 쓴다.

## 끝에 내놓을 것
```
## 인터뷰 결과 (<날짜>)
- 모호함: 목표 0.1 / 범위 0.2 / 합격 0.1 / 제약 0.2
- 정한 것: (한 줄씩, 누가 정했는지)
- 용어집에 쓴 것: (용어 한 줄씩)
- [가정]으로 남긴 것: (assumptions.md에 쓴 줄)
- 아직 열린 것: (문서에 [확인 필요: 무엇]으로 남긴 것, docs/team/questions.md로 보낼 질문)
- 문서에 쓴 곳: (브랜치, 파일·절)
- ADR: (쓴 것 / 쓰지 않고 design.md 결정 칸에 쓴 것)
```

## 하지 않는 것
- 답을 대신 정하지 않는다. 추천은 첫 보기에 "(추천)"과 이유 한 줄로만.
- 코드를 직접 읽거나 고치지 않는다. 기존 코드에 대한 사실은 researcher가 찾는다.
- `main`에서 문서를 고치지 않는다.
