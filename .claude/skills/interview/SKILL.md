# 인터뷰: $ARGUMENTS

목표: 사람이 머릿속에만 가진 결정을 문서로 꺼낸다. 질문은 한 번에 하나, 가장 모호한 것부터.

## 장치 세 개 (deep-interview에서 가져온 것)
1. **모호함 점수**: 아래 네 칸을 0~1로 매기고 매 질문 뒤 다시 매긴다. 넷 다 0.2 이하가 되면 끝낸다.
   - 목표(무엇을 왜) / 범위(안 할 것) / 합격 기준(숫자·예시) / 제약(시간·비용·데이터·API 상한)
2. **가장 약한 칸 먼저**: 점수가 가장 높은(가장 모호한) 칸에서 질문 하나를 고른다.
3. **반대로 묻기**: 세 번째 질문마다 "이걸 안 하면 무엇이 깨지나?" 또는 "반대로 하면?"을 묻는다. 당연해 보이는 가정을 흔든다.

## 하는 법
1. 먼저 읽는다: `docs/product.md`, (있으면) `docs/features/<기능>/requirements.md`, `docs/assumptions.md`.
2. 이미 문서에 답이 있는 것은 묻지 않는다. 읽은 것으로 점수를 먼저 매긴다.
3. 질문은 보기 2~4개 + "기타"로 낸다. 각 보기에 무엇이 달라지는지 한 줄.
4. 사람이 "몰라", "나중에"라고 하면 `docs/assumptions.md`에 `[가정]` 줄로 남기고 넘어간다 (언제 잴지 한 줄).
5. 끝나면 결과를 붙일 문서(requirements/design/product)에 넣을 줄을 **제안만** 한다. 파일은 사람이 "넣어"라고 하면 고친다.

## 끝에 내놓을 것
```
## 인터뷰 결과 (<날짜>)
- 모호함: 목표 0.1 / 범위 0.2 / 합격 0.1 / 제약 0.2
- 정한 것: (한 줄씩, 누가 정했는지)
- [가정]으로 남긴 것: (assumptions.md에 넣을 줄)
- 아직 열린 것: (docs/team/questions.md로 보낼 질문)
- 문서에 넣을 줄 제안: (파일·절·문장)
```

## 하지 않는 것
- 답을 대신 정하지 않는다. 추천은 보기 하나에 "(추천: 이유)"로만.
- 코드를 읽거나 고치지 않는다.
