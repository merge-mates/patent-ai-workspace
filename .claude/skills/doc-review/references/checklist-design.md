# 설계(docs/features/<기능>/design.md, docs/architecture.md) 체크리스트

## requirements와 맞는가
- [ ] requirements의 합격 기준마다 "설계의 어디가 그걸 만족시키나"가 짚인다
- [ ] requirements에 없는 기능을 몰래 늘리지 않았다

## 모양
- [ ] 주고받는 데이터 모양(표·응답 JSON)이 예시와 함께 있다
- [ ] 인터페이스(AI 모듈 입력·출력, API)가 바뀌면 바뀐 모양이 적혀 있다 (`docs/api/openapi.yaml`은 쓰고 있으면 같이)
- [ ] 흐름(요청 → 처리 → 응답)이 단계로 있다. 실패할 때 어떻게 되는지도
- [ ] 빈 결과·에러일 때의 동작 (화면은 시연용이라 시연 흐름만)

## AI
- [ ] 모델 호출이 어디서 몇 번 일어나는지, 대략 비용
- [ ] 프롬프트 파일 위치, 실험 설정(config) 키 이름
- [ ] (비교 실험 예) 공통 칸이 둘이 따로 구현할 만큼 정해졌나: 인터페이스 입력·출력, 평가 세트·지표, 데이터, 채점 스크립트
- [ ] 에이전트 도구가 있으면 도구마다 "언제 쓰고 언제 안 쓰나"

## 결정
- [ ] 이 설계 안에서 고른 것마다: 고른 안, 버린 안, 이유 한 줄
- [ ] ADR 세 조건(되돌리기 어렵다 / 이유를 모르면 이상해 보인다 / 진짜 선택지가 있었다)이 다 맞는 결정이면 `docs/decisions/`로 빼야 한다고 표시

## 구현 준비
- [ ] 구현 계획(tasks.md)으로 쪼갤 수 있다 (task가 반나절 안쪽, 이슈 하나에 2~5개로 보인다)
- [ ] 테스트 방법(가짜 응답, 녹화 응답)이 정해져 있다
- [ ] 7절 `어디서 테스트하나`(가장 바깥 경계 한 곳)가 비어 있지 않다
- [ ] `[확인 필요]`가 하나도 남아 있지 않다 (`[가정]`은 된다)
- [ ] 재 보지 않은 숫자는 `[가정]`
