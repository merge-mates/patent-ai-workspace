# OA 논점별 초안 채점 초안

관련 [#345](https://github.com/merge-mates/patent-ai-workspace/issues/345)와 [#46](https://github.com/merge-mates/patent-ai-workspace/issues/46). 먼저 OA 원문에서 논점을 확정하고, 고정한 논점을 동일 사건의 모든 초안에 적용한다.

## 1. 논점 목록

심사관의 주장을 독립적으로 답할 수 있는 단위로 나누고 해당 청구항, 거절이유, OA 원문 위치와 인용문을 기록한다. 청구항 두 개에 공통으로 얹힌 동일 주장은 한 번만 기록한다. OA에 드러나지 않는 주장은 검수 대상으로 따로 둔다. 초안을 읽기 전에 분모를 확정한다.

예시. 심사관이 “D1은 센서 기록을 50ms 이내에 수행한다”와 “D2의 보정 회로를 D1에 연결할 동기가 있다”를 제시했다면 개시 여부와 결합 이유를 별개 논점으로 만든다. 의견서가 첫 주장만 반박했다면 첫 논점 응답, 두 번째 논점 누락이다.

## 2. 초안별 판정

| 항목 | 라벨 | 기록 |
|---|---|---|
| 논점 응답 | 직접 응답·일부 응답·누락·판정 불가 | 의견서 또는 보정안의 해당 문장과, 주장 중 답한 범위 |
| 응답 근거 | 뒷받침·부분 뒷받침·충돌·확인 불가·해당 없음 | 근거 ID와 실제 원문 구절. 원문 부재와 무근거 주장을 구분 |
| 보정 근거 | 최초 명세서가 지지·부분 지지·충돌·확인 불가·해당 없음 | 청구항의 바뀐 문구와 최초 명세서 근거 ID |
| 문서 간 일관성 | 일치·불일치·확인 불가 | 의견서가 설명한 보정과 실제 생성 문구의 관계 |

내용상 틀린 답도 논점에 직접 답했다면 응답으로 세고, 근거 항목에서 감점한다. 검색 자료가 없으면 충돌이라고 판단하지 않고 이유를 기록한다. 인용된 번호가 맞아도 원문이 주장을 지지하는지 별도로 확인한다. 지원 범위 밖 논점과 실행 실패를 별도 집계하고 분모에서 어떻게 처리했는지 기록한다.

## 3. 채점 실행과 검증

- 고정 논점과 원문 근거를 주고 초안 조건을 가린다. 모델 응답은 논점 ID, 결정, 인용된 초안 문장·근거 구절, 판정 이유를 구조화해 저장한다. 확인할 원문이 없는 경우를 분리한다.
- 사람 검수는 누락·충돌·확인 불가와 조건별 차이가 큰 행에서 먼저 수행한다. 동일 조건의 재채점과 사람이 매긴 라벨 일치를 보고 보정할 규칙을 결정한다.
- 실제 제출본 방향·보정 종류·문단 일치는 별도로 채점한다. 실제 지원 문서를 LLM 저지의 첫 초안 검증 입력에 섞지 않는다.
- 결과는 직접 응답 수/전체 논점 수, 확인 가능 근거 중 지지 행 비율, 근거 확인 가능률, 미응답·충돌·자료 없음 수를 같이 낸다.

[PatRe 논문](https://arxiv.org/html/2605.03571)과 [공개 채점 프롬프트](https://github.com/AIforIP/PatRe/blob/main/config/prompt_templates.json)의 개별 논점 직접 응답 개념을 참고했다. 표의 논점별 라벨은 이번 파일럿의 검증 방식이다.
