# 인용문헌 BM25에서 질의 낱말을 한 번씩만 세기

**가설**: 법령처럼 질의(OA 당시 청구항)에서 반복되는 낱말을 한 번씩 세면 흔한 낱말 쏠림이 줄어 hit가 오른다.
**종류**: 설정 비교
**바꾼 것 (하나)**: `bm25.unique_query_terms` false → true

## 결과 (scores.json)
| 지표 | 기준선 | 이번 | 차이 |
|---|---|---|---|
| hit@1 / @3 / @5 / @10 | 0.118 / 0.324 / 0.500 / 0.618 | 0.147 / 0.368 / 0.412 / 0.588 | +0.029 / +0.044 / −0.088 / −0.029 |
| recall@5 | 0.330 | 0.249 | −0.081 |
| 무작위 대비 recall_ratio@5 | 2.14배 | 1.62배 | |
| 비용($) / 외부 호출 | 0 / 0 | 0 / 0 | |

- n = 68줄 (#129 채점기: 범위 밖 정답 줄 1개·항목 10개 뺌, 기준선과 같음). 문항 수로 hit@5 34 → 28, hit@1 8 → 10. n=68에서 비율의 표준오차가 약 0.06이라 노이즈 범위 안이다 (한 번 돌림, 문항별 짝 비교 안 함).
- 합친 코드로 기준선 설정을 다시 돌려 metrics·failures가 기준선 scores.json과 같은 것을 확인했다 (#129 전 채점기에서. 그 파일은 고치지 않음).

## 실패 유형 (개수)
| 유형 | 기준선 | 이번 |
|---|---|---|
| excluded_no_location / same_as_other | 3 / 33 | 3 / 33 |
| excluded_gold_not_in_scope / items | 1 / 10 | 1 / 10 |
| CQ 후보 | 26 | 28 |

## 해석
- 앞 순위는 조금 오르고 뒤 순위는 내린다. 이득도 손해도 확인되지 않았다.
- 법령은 true가 크게 낫고(hit@1 0.211 → 0.632) 인용문헌은 노이즈 안이라, 두 말뭉치를 하나로 맞추면 true 쪽이 잃을 것이 적어 보인다. 정하는 건 11/24 CQ 볼 때.
