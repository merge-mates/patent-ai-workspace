# 보정안을 의견서 입력으로 넣기, tune 4건

## 돌리기 전에 정한 것 (2026-11-25, 결과를 보기 전)
- 사건: 보정 실험 예비 27건에서 G1 둘, G4a 하나, G4b 하나를 묶음마다 출원번호 순 앞에서 고른다. 짚인 항 중 종속항이 5개 이상이고 cite-idx-v5 본문 빠짐 목록에 없는 사건만. E의 점수는 고르는 데 쓰지 않는다. 테스트 20건과 검사 17건은 쓰지 않는다. case1~4로만 적고 번호 대응은 git 밖.
- 보정안은 이미 있는 E 추천 1번 안 그대로 (다시 부르지 않음).
- 의견서 세 조건. 같은 모델(서비스 F4와 같은 claude-haiku-5-5 medium), 같은 자료, 글 한 번씩.
  - `direction` 방향만: 전략 글 + 항 번호·고침/삭제 (지금 F4의 `amendment_core`와 같은 수준, 문구 없음)
  - `amend` 보정안: 위 + 보정 뒤 문구·이유
  - `amend_check` 보정안+점검: 위 + "보정한 항과 종속항 논점을 빠뜨리지 않기" 지시
- 채점: 재아 채점기(`m3-i2-oa-draft-judge-pilot`)의 프롬프트·입력 준비·출력 검사를 고치지 않고 쓴다. 모델 호출만 구독(`claude -p`, claude-opus-5-5 high)으로 바꾼다. 논점은 초안을 만들기 전에 OA만 보고 고정한다. 초안 조건은 가린다.
- 더한 채점: 보정한 항마다 의견서가 설명했나 (`prompts/coverage.md`, 재아 프롬프트와 따로).
- 주 지표: 보정한 항 설명률 (explained / 보정한 항). 함께: 보정안과 의견서가 어긋난 항, 종속항에만 걸린 논점의 direct 수, 전체 논점 direct 수, 인용 근거 supported 비율(나빠지지 않았나).
- 의견서의 보정 근거(명세서 지지)는 세 조건의 보정안이 같아서 재지 않는다.

## 읽는 법
- 보정안 문구를 넣은 것만으로 설명률은 올랐지만(84% → 93%), 논점 누락은 줄지 않았다(27 → 32). 종속항 누락이 준 것은 "항을 하나씩 대조하라"는 점검 지시를 함께 준 조건에서다. 입력과 지시를 나눠 재서, 둘이 다른 일을 한다는 것이 보인다.
- 점검 지시의 대가: 글이 1.7배, 인용 수가 늘고 틀린 근거(contradicted·unsupported)가 1 → 4. supported 비율은 거의 같다. 종속항 direct도 25 → 28로 조금이고, 누락이 일부 응답(partial)으로 옮겨 간 몫이 크다.
- phantom 14는 1회·2회 모두 case2 보정안 초안 하나씩에서 나왔다 (그대로 둔 종속항의 "인용 번호만 정리").

- 설명률 차이는 case1에 몰려 있다 (방향만 9/18, 나머지 두 조건 18/18씩). 나머지 세 사건은 방향만도 53/56이라 여유가 작다.

## 한계
- 4건·2회다. 통계로 말하지 않는다. 예비 사건은 보정 정답을 이미 연 묶음이라 시험 세트가 아니다.
- 기준선은 재아의 F4 초안이 아니다. 같은 자료(OA 전체, 발췌 인용문헌, 출원서)에서 입력만 바꾼 의견서라 F4 파이프라인(F1→F3→F2→F4, 묶음마다 따로 호출)보다 자료가 많다. 재아의 "51개 중 43개 누락"과 숫자를 비교하면 안 된다.
- 논점 고정과 채점은 구독의 claude-opus-5-5, 초안은 claude-haiku-5-5다. 재아 채점기의 gpt-4.1 API와 다르고, 사람 검수는 안 했다.
- `coverage` 채점은 새로 만든 것이라 사람 라벨과 맞춰 보지 않았다.
- 인용문헌 원문: 한글 공보는 재아 코드, 미국·논문 글은 여기서 더한 읽기를 썼다. case2의 D2는 발췌를 3만 자에서 잘랐다.
- 심사기준·법령 근거 자료는 넣지 않았고(F2 없음), 실제 의견서와 비교하지 않았다.
- 보정안 자체의 질은 이 실험이 재지 않는다 (예비 27건 결과는 나아진점.md).
