# 인용문헌 검색 둘째 점수 (노이즈 C안, 판 2)

**가설**: 정답과 같은 분야·비슷한 낱말의 공보(C안)를 섞으면 상관없는 인용문헌(B안)만 섞을 때보다 문단 Hit@k가 더 내려가고, 검색 방식(BM25·벡터·하이브리드) 사이 차이가 드러난다.
**종류**: 평가 범위 비교 (검색기는 m2-i2 설정 그대로)
**바꾼 것**: 줄마다 검색 범위와 색인. 정답은 그대로(tune v2, 68줄). 판 3(11/23) 전에 먼저 쟀다 (재아 요청: OA를 늘릴지 일찍 정하려고).

## 결과 (n=68, 11/22, 비용 0)
같은 색인 `cite-idx-v4`에서 범위만 바꿨다. "문헌 안"은 주 점수(그 인용문헌 하나 안)다. v4 문헌 안 점수가 v1·v2 기준선(m2-i1 BM25 0.618, m2-i2 하이브리드 0.706)과 같아 색인이 맞게 들어간 것을 확인했다.

## 해석 (11/22 은진·Claude, 재아 확인 전)
- C를 더하면 세 방식 모두 Hit@10이 조금 더 내려가고(BM25 −0.03, 벡터 −0.02, 하이브리드 −0.04), 문헌 Hit@1이 더 크게 내려간다(−0.04~−0.07). 비슷한 공보가 1등 조각을 가져가는 것이 C의 효과다.
- C 범위에서 벡터·하이브리드(0.338)가 BM25(0.265)보다 Hit@10이 0.07(68줄 중 5줄) 높다. 다만 n=68에서 Hit@10 0.3 근처의 95% 구간은 대략 ±0.11이라 이 차이도 우연과 구분되지 않는다. 짝지은 비교(같은 줄끼리, `eval.retrieval.compare`)는 아직 안 했다.
- 그래서 문헌(노이즈)을 더 늘리기보다 평가할 질의(OA) 수를 늘려야 방식 차이를 볼 수 있다는 11/22 은진·재아 판단과 맞는다. 판 3(tune 30건 정답)으로 다시 잰다.
- 노이즈 상위 오답 확인은 아래 절 (#178 T4).

## 노이즈 상위 오답 확인 (11/22, #178 T4)
하이브리드 C 범위에서 상위 10에 정답 위치가 없던 45줄 중, 상위 10에 노이즈 문헌 조각이 든 37줄을 봤다. 줄마다 가장 위 노이즈 조각 하나만 봤다(33줄은 1등). 그 조각이 청구항 구성요소를 실제로 보여 주는지 셋 중 하나로 판정했다.
- 관련: 이 글만으로 구성요소의 핵심 내용이 드러나 심사관이 근거로 짚었어도 이상하지 않음
- 일부: 비슷한 말·분야지만 구성요소의 핵심 일부만 보여 주거나 다른 목적으로 씀
- 무관: 구성요소와 실질적으로 상관없음 (글이 잘려 애매하면 무관 쪽으로)

판정한 쪽: 37줄 전체는 이 실험 맥락을 모르는 판정 에이전트 3개가 따로 했다 (Claude Code 서브에이전트, 이 세션과 같은 모델. 확인표 하나만 주고 다른 파일·서로의 판정은 못 봄. 모델 호출 모듈 밖이라 비용 기록은 없다). 일치는 단순 일치율(κ 아님)로 셋 다 같음 31/37, 둘씩 0.86~0.92. 사람이 직접 훑지 않고 에이전트 판정으로 갈음했다 (사람 검수를 돕는 일회성 판정, 11/22 은진 결정, `docs/evaluation/search-gold.md` 5절). 대신 다수결 "관련" 2줄과 "일부" 4줄(B 같은 OA·다른 OA, C 둘씩)을 새 판정 에이전트 3개에게 다수결 칸을 가리고 다시 맡겼고, 6줄 모두 셋 다 처음 다수결과 같았다 (관련 2, 일부 4).

| 다수결 | 줄 수 | B 노이즈 (tune 인용문헌, 같은 OA의 다른 인용 포함) | 그중 같은 OA | C 노이즈 (비슷한 공보) |
|---|---|---|---|---|
| 관련 | 2 | 2 | 1 | 0 |
| 일부 | 16 | 13 | 9 | 3 |
| 무관 | 19 | 11 | 2 | 8 |

- 완전히 관련 2/37, 일부 16/37 (일부를 맞힌 것으로 칠지는 정하지 않음). 관련 2줄은 같은 OA 인용문헌 1줄, 다른 OA 인용문헌 1줄이다.
- 관련 2줄을 맞힌 것으로 치면 하이브리드 C Hit@10은 0.338 → 0.368(23/68 → 25/68)이다. BM25·벡터는 이 보정을 하지 않았다. "방식 차이는 우연과 구분 안 됨"은 보정이 방식마다 비슷하다는 전제에서다.
- C가 맨 위였던 11줄 중 관련 0 (일부 3, 무관 8).
- 판정 표(질의·조각 글·판정): 드라이브 `merge_mates/05_평가정답/tune_search_noise_b_1121/t4_review/` (`hybrid_c_top_noise_judged.csv`, 판정자별 `judge_A·B·C.csv`, 다시 판정 `recheck_6.csv`). 발송번호와 청구항 글이 있어 git에는 넣지 않는다.
- 표 다시 뽑기: `uv run python -m eval.retrieval.noise_review --cq work/retrieval/m2-i3-cite-search-hybrid-noise-c/cq_candidates.jsonl --chunks data/processed/cite_search/cite-idx-v4.jsonl --pool data/goldsets/tune/retrieval/cite_pool_bc.yaml --gold data/goldsets/tune/retrieval/cite_gold.jsonl --out work/t4_review/hybrid_c_top_noise.csv` (CQ 후보 파일은 하이브리드 C 채점이 남긴다). 정답 글 칸은 참고용이고 도면만인 위치 등 일부 줄은 비어 있다.
