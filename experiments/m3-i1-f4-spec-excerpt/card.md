# F4 보정 프롬프트 명세서 발췌 (이슈 #42)

**가설**: 보정 프롬프트에 최초 명세서 쪽 글자 전체 대신 차이점 구성요소·청구항 글자와 겹치는 문단 상위 5개(청구범위 덩어리는 후보에서 뺌)만 넣으면, 보정 단계 입력 토큰(전체의 58%, m3-f4-skeleton)이 크게 줄고 근거 위치 대조 통과 수(비율)는 그대로다. 근거 대조는 켜도 원문 전체로 하니, 통과 수가 떨어지면 모델이 발췌에 없는 곳을 못 보아 근거를 못 댄 것이다.
**종류**: 설정 비교
**바꾼 것 (하나)**: `amendment_spec_excerpt.enabled`: false → true (`top_n`: 5)
**비교**: 끔 = first-score 3회, 켬 2회. 코드 판 차이: first-score는 main 9eb8237, 이 브랜치는 #211 위(묶음 호출 실패 보류). 끔 프롬프트는 같아 호출 실패가 없으면 결과가 같다.
**주 지표**: 점수 표(`experiments/index.md`)는 F4 채점기 metrics 키만 받아 머리말에는 `direction_top1`을 적었다. 채택 판단은 근거 위치 대조 통과 수(비율, 채점기 밖, `summary.json`에서 셈). 함께 보정 단계 입력 토큰·비용. `direction_top1`은 `$spec`이 보정 프롬프트에만 들어가 이 스위치로 바뀔 수 없으니, 안 바뀌어야 한다 (바뀌면 실행 사이 흔들림 확인용).
