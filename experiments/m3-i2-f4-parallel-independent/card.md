# 병렬 독립항 맞추기 규칙 (ADR 0005 5번 사건 전체 검사 후보)

**가설**: 실무에서는 한 독립항에 종속항 특징을 합치면, 같은 거절이유의 병렬 독립항(장치·방법·매체)에도 같은 특징을 넣는다. 그래서 모델이 한 독립항에 고른 출처를 코드가 병렬 독립항에 옮기면, 출처 정밀도를 크게 잃지 않고 병렬 독립항 출처 회수가 오른다.
**종류**: 설정 비교 (규칙 있음 / 없음). 규칙은 모델 출력 뒤에 얹는 코드라, 같은 모델 출력을 두 번 채점한다.
**결정 문서**: [ADR 0005](../../docs/decisions/0005-f4-amendment-scope.md) 5번, 1차 실험 [사후 분석](../m3-i2-f4-amendment-scope/card.md)

## 왜 새 세트인가
- 규칙(1차 실험의 K3)은 1차 결과를 본 뒤 만들었다. 같은 8건에서 다시 재면 결과에 맞춘 규칙을 결과로 확인하는 셈이라, 1차에 쓰지 않은 세트에서 잰다.
- tune30 F4 검수 정답 v0 20건은 1차 8건·F4 tune 정답 10건과 겹치지 않는다 (2026-11-24 확인).
  - 20건 중 11건에 종속항 병합이 있다. 고유 (보정 항, 출처) 쌍은 38개다.
  - 병렬 / 같은 가족으로 나눈 수는 **아직 세지 않았다**. 문턱을 먼저 적기 위해서다 (A단계 0번에서 센다).
- report 세트는 열지 않는다.
- 이 20건에는 F1 정답·F1 예측·F3 결과가 없다. OA 시점 입력(`data/processed/cases/<출원>/<발송>/`)과 청구항 이력은 20건 모두 있다.

## 규칙 정의 (돌리기 전에 고정)
같은 거절이유 r의 진보성·신규성 묶음들에서, 1등 후보가 독립항 c0에 `add` + `other_dependent` + `source_claims = S`를 냈다고 하자. 그러면 r의 거절 대상인 **다른 독립항 p**마다, p가 든 묶음의 1등 후보에 (p, `add`, `other_dependent`, S − {p})를 더한다.
- p에 이미 `add`·`other_dependent`가 있으면 출처를 합친다.
- p가 `unchanged`가 아닌 다른 종류(`limit`·`delete` 등)면 건드리지 않는다.
- 독립항 = 인용 관계표에서 인용이 없는 항.
- 1차 실험 `work/f4_amendment_scope/combo.py`의 `propagate_parallel` 그대로 쓰고, 고치지 않는다.

## A단계: 규칙 전제 확인 (모델 호출 0, 비용 0)
정답만으로 "정답 출처를 한 독립항에 고르면, 규칙이 병렬 독립항에 옮긴 것도 정답인가"를 본다 (모델이 완벽하게 골랐다고 둔 상한).

0. 준비
   - 20건의 OA 시점 청구항 글자를 1차 F3 실행 스크립트와 같은 길(`eval/retrieval/claim_history.py` `claims_at_oa_with_stats`)로 만든다.
   - 인용 관계표를 1차 `deps.py` 규칙으로 만들고, 못 읽은 항 수를 적는다.
   - 거절이유 대상 항은 정답 행(거절이유 × 청구항)에서 읽는다.
   - 이 세트에는 거절이유 종류(F1)가 없다. 그래서 같은 (보정 항, 출처)가 여러 거절이유에 있으면 하나로 센다.
1. 정답 쌍 (c, n)을 나눈다: c와 n이 같은 독립항 가족이면 "같은 가족", 아니면 "병렬". 건수를 이 카드에 적는다.
2. 규칙 상한 계산
   - 정답의 같은 가족 쌍 (c0, n)을 "모델이 고른 것"으로 두고 규칙을 돌린다.
   - c0와 같은 정답 행 거절이유에 함께 든 다른 독립항 p에 (p, n)을 만든다.
   - `rule_precision` = 만든 (p, n) 중 정답에 있는 비율
   - `rule_coverage` = 정답 병렬 쌍 중 규칙이 만든 비율

**A단계 문턱 (돌리기 전에 정함):**
- 병렬 쌍이 **5개 미만**이면 이 세트로는 판정하지 않고 멈춘다 (세트를 더 찾는다).
- `rule_precision` ≥ 0.8 **이고** `rule_coverage` ≥ 0.6이면 전제 유지 → B단계로 간다.
- `rule_precision` < 0.8이면 규칙이 실무보다 넓다. 원인 표를 만든다. 예: 장치항에만 넣고 매체항에는 안 넣음, 다른 거절이유. 규칙을 좁히는 안을 적고 B단계로 가지 않는다.
- `rule_coverage` < 0.6이면 병렬 쌍 대부분이 "한 독립항 고르기 → 옮기기"로 설명되지 않는다. 원인 표를 만든다 (예: 병렬 독립항에만 다른 종속항을 넣음).

## B단계: 끝에서 끝까지 (A 통과 때만, 비용 듦, 진행 전에 다시 묻는다)
- 실행: 20건에 F3(앱 기본 설정)를 돌린다. 그다음 1차 ③과 같은 프롬프트·모델(Sonnet 5.5 medium)로 방향 후보를 2회 부른다.
- 비교: 같은 모델 출력에 규칙 없음 / 있음을 채점한다. ①은 부르지 않는다 (이 실험의 변수는 규칙 하나).
- **열린 결정 (B 전에 사람이 정함): OA 정보의 출처.**
  - 지금 합의는 "F1 정답을 OA 기준으로"인데, 이 20건에는 F1 정답이 없다.
  - 안 1: F1을 새로 돌려 예측을 쓴다. 합의와 다르고, F1 오류가 섞인다.
  - 안 2: 20건 F1 정답을 먼저 만든다. 사람 검수가 필요하다.
  - 안 3: B단계를 하지 않고 A 결과로 ADR 5번 규칙 후보를 정한다. 모델 쪽은 1차 8건 결과를 근거로 둔다.
- 비용: F3 20건 + Sonnet 묶음 수 × 2회. 0번 준비 뒤 묶음 수와 추정 비용을 이 카드에 적고 묻는다.

**B단계 문턱 (돌리기 전에 정함, 두 회차 모두):**
1. `parallel_pair_recall`: 규칙 있음 − 규칙 없음 ≥ 0.2 (절대값)
2. `source_precision_top1`: 규칙 있음 ≥ 규칙 없음 − 0.10
3. `over_change_target`: 규칙 있음 ≤ 규칙 없음 + 1
4. `same_family_pair_recall`: 규칙 있음 = 규칙 없음 (규칙이 같은 가족 쌍을 건드리지 않았는지 확인. 다르면 코드 오류로 멈춤)

## 지표 (B단계, 1차 `score.py`를 그대로 쓰고 병렬·같은 가족 나눔만 더함)
| 지표 | 정의 |
|---|---|
| **`parallel_pair_recall`** (주) | 정답 병렬 쌍 중 후보 어느 것이든 (c, `add`, `source_claims ∋ n`)을 낸 비율 |
| `same_family_pair_recall` | 같은 가족 쌍에서 같은 계산 |
| `source_precision_top1` | 1등 후보가 낸 출처 중 정답 출처 비율 |
| `over_change_target` | 정답 `none` 행을 1등 후보가 바꾼 수 |

## 순서
1. A단계 0~2. 결과와 문턱 판정을 이 카드에 적는다 (커밋).
2. A 통과면 B단계의 OA 정보 출처(안 1~3)와 비용을 묻는다.
3. B단계를 하면 결과·원인 표를 적고, ADR 0005 5번에 규칙을 넣을지 적는다.

## 한계
- 정답은 거절 대상 항 행만 있어, 병렬 독립항이 거절 대상이 아니면 그 보정은 보이지 않는다.
- A단계는 "모델이 정답 출처를 골랐다면"의 상한이다. 모델이 출처를 틀리게 고르면 규칙이 틀린 출처도 옮긴다 (1차 K3에서 정밀도 0.50 → 0.45).
- tune30 정답은 v0 (검수본, 은진 님 초안 + 삭제 행 원문 대조)이다. 정식 tune 판(VERSION 2)에 들어가지 않았으므로 점수는 tune VERSION 2 점수와 섞지 않는다.

## 결과: A단계 (2026-11-24, 모델 호출 0)
스크립트·산출물은 git 밖 `work/f4_parallel_independent/` (`precheck_a.py`, `precheck_a.json`, `deps_review.md`, `cause_table.md`). 건 이름은 t1~t20 (정답 zip 파일 이름 순서).

**0. 준비**
- 20건 모두 OA 시점 청구항을 만들었다 (294항).
- 1차 실행에서 쓴 `data/raw/cases`에는 이 20건이 없어, 같은 청구항·행정이력 파일을 tune 사건 묶음(`data/goldsets/tune/case_full`)에서 입력 준비 용도로만 읽었다.
- 인용 관계를 못 읽은 항은 1항이다 (t15 제12항). 사람 대조는 아직이다.

**1. 정답 쌍 나누기:** 고유 38쌍 = 같은 가족 29 + **병렬 9** (5건: t1·t8·t10·t14·t16) + 모름 0. 병렬이 5개 이상이라 판정한다.

**2. 규칙 상한**
| 지표 | 값 | 문턱 | 판정 |
|---|---|---|---|
| `rule_coverage` | 9/9 = 1.0 | ≥ 0.6 | 통과 |
| `rule_precision` | **9/40 = 0.225** | ≥ 0.8 | **미통과** |

**판정: A단계 미통과 → 계획대로 B단계로 가지 않는다.**

**원인** (`cause_table.md`): 규칙이 옮긴 40개 중 틀린 31개를 정답에서 보면 세 가지다.
- **20개 (6건): 병렬 독립항 p 쪽의 쌍둥이 종속항을 출처로 보정했다.** 같은 내용의 종속항으로, 글자 유사도는 0.80~0.96이다.
  - "같은 특징을 병렬 독립항에도 넣는다"는 전제는 맞았다.
  - 규칙이 c0 쪽 종속항 번호를 그대로 옮겨 번호가 틀린 것이다.
- 10개 (5건): p에 종속항이 아닌 다른 한정을 넣었다.
- 1개: 병렬 독립항마다 다른 종속항을 골랐다.

**진단** (결과를 본 뒤 만든 규칙 변형이라 판정에 쓰지 않음):
- 쌍둥이는 정답을 보지 않고 p 가족의 모든 종속항 중 글자가 가장 비슷한 항으로 찾았다.
- V1 "쌍둥이(유사도 ≥ 0.7)가 있을 때만 그 번호로 옮김": 정밀도 **20/20**. 이 20쌍은 정답에서 p의 "같은 가족" 쌍이라 병렬 쌍 회수는 0/9다.
- V2 "쌍둥이 우선, 없으면 번호 그대로": 정밀도 29/40 = 0.725, 병렬 쌍 9/9. 그중 "쌍둥이 없음" 갈래만 보면 9/20 = 0.45다.

## 해석 (Claude 초안, 사람이 고칠 것)
- 처음 규칙(번호 그대로 옮기기)은 이 세트에서 정밀도가 너무 낮아 사건 전체 검사 규칙으로 쓰지 않는다.
- 실무 패턴은 둘로 갈린다. 이 세트에서는 쌍둥이 쪽이 20쌍으로 병렬 9쌍보다 많다.
  - **쌍둥이 종속항이 있으면 그 쌍둥이를 합친다.**
  - **쌍둥이가 없으면 다른 가족 종속항을 그대로 넣는다.** 이 경우 1차 세트 case7처럼 병렬 쌍으로 기록된다.
- 그래서 다음 규칙 후보는 둘로 나뉜다. 둘 다 결과를 본 뒤 만든 것이라 다른 세트에서 따로 재야 한다.
  1. 쌍둥이가 있으면 자동으로 옮긴다 (V1: 이 세트 20/20).
  2. 쌍둥이가 없으면 옮기지 않고 "병렬 독립항 확인 필요"로만 표시한다 (이 세트 정밀도 0.45라 자동 후보로 내기 어려움).
- 1차 세트의 K3 결과(병렬 쌍 회수 상승)는 "쌍둥이 없음" 갈래가 맞은 경우였다. 이 세트의 0.45와 함께 보면, 그 갈래를 자동으로 옮기면 틀린 후보도 비슷한 수만큼 늘 수 있다 (판단).
